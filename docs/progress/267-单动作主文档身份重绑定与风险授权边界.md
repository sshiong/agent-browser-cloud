## 实现与边界

单动作此前即使指向同一主文档中的同一稳定实体，也只能使用派发时的精确 Target
Revision。输入值、焦点等变化可能推进 Revision；已有 Batch 的稳定身份路径没有覆盖
这些单动作。本次增加内部 Protobuf tag 27/28，保留原 Target Ref、Revision 与 State
基线，控制面在完成原输入和 Capability 校验后捕获唯一主文档实体身份。

- 只向声明 `agentSingleTargetRebind=main-document-element-v1` 的 Node 派发身份字段。
  历史调用、N−1 Node、缺实体身份、子 Frame 与不支持的工具保持原精确围栏。
- 风险授权同时绑定数据库 Task 风险、Plan Step 风险与已验证 Capability 风险；普通
  重绑定只允许 R0/R1 Task 与 R0/R1 Step，签名风险必须与 Step 一致。
- 既有 AUTONOMOUS 一次性敏感输入允许 R2 以内 Task 的 CREDENTIAL/OTP `TYPE_TEXT`
  重绑定；仍要求密文、敏感目标允许标记和原重试上限。一般 R2 数据更改、R3 账号、
  R4 支付与 R5 安全决定不获得本次身份放宽。未知 Task 风险默认精确围栏。
- Node 要求同一 Session、单调 State/Revision、同版本 Hash 一致、完整质量、当前唯一
  Active Tab、全页 DOM/Layout/Focus/Route/Network Quiet 与新鲜无 Native Dialog 证明。
  当前目标必须唯一、主 Frame、可交互、可见、可用、视口内、不遮挡且 Bounds 有效。
- 原 Ref 必须是该稳定 ID 本身，或该 ID 在原 Revision 的精确摘要引用；同 URL 新文档、
  Route/Tab/实体变化、未知或重复 ID 都拒绝。拖拽必须同时证明两个主文档目标。
- 身份只在执行前重绑定一次；后续输入解析仍用最新精确 Revision。竞态失败不重发输入。
  Operation/Epoch/取消、真人输入优先级、一次性 Capability 与 Secret 用途保持有效。

公开 API 没有新增入口或放宽权限；255 Operations / 357 Schemas 与 SDK 保持不变。
本次没有开放 Opaque Frame 输入，也没有实现稳定区域 fallback。
