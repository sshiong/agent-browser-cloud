## 需要解决的缺口

MutationObserver 在真实往返后得到零条 Mutation，最终值比较不能还原这段历史。

## 已排除的实现假设

私有自有 Chrome 探测确认以下限制：

- Main Realm 的原生 setter 函数调用断点覆盖直接调用与另一 Realm 的原生 setter；
  从隔离 Realm 取得的同名 setter 断点不覆盖 Main Realm 的这两种调用。
- Debugger.paused 的 callFrames 没有原生 setter 帧，也没有 Node 类型的 this。
  不能从暂停帧直接推断实际输入元素，更不能读取调用方局部变量来猜测。
- 两个客户端设置同一原生 setter 断点得到相同 ID；各自事件都只列出这个 ID。
  因此 hitBreakpoints == [ownedId] 不足以证明暂停独占归属。
- 已暂停时仅关闭观察连接，在另一个 Debugger 客户端仍启用的情况下不会让页面继续。
  不能把 socket drop 当成可靠恢复机制。

这些限制使“断点暂停后按 ID 自动 resume”的候选路径不成立。本次测试没有任何
Debugger.resume 命令；意外暂停直接以固定分类失败并停止本测试自己的 Chrome。

## 新的候选机制

原生函数断点条件能使用实际接收元素 this 和 setter 参数。条件调用该元素上的
只追加回调，随后始终返回 false。回调不可替换、不可删除；计数保存在严格模式
闭包内，只由 Node 持有的 RemoteObject 读取函数访问。页面主动调用回调只能增加
计数，不能清零。实际 setter 的语义保持，观察客户端不触发暂停。

自有 fixture 当前只验证 checked，不读取密码、OTP 或任何输入文本。两个元素分别
计数，修改第二个元素不会增加第一个元素计数。跨 Realm 调用也能命中接收元素上
的回调。另一客户端启用 Debugger、设置自己的不同恒 false 条件和移除自己的断点，
均未覆盖本观察客户端的条件或移除其观察。

## 仓库可重复测试

实现位置：`apps/browser-node/crates/state-collector/src/native_property_probe.rs`，
只在 cfg(test) 中编译。它单独启动自己的 Chrome 与私有 Profile，Chrome 持有系统
分配端口并发布 DevToolsActivePort；通过精确 Target ID 连接新建自有页面。
每条命令最多三秒、4096 消息、128 KiB。失败只输出固定分类，不输出浏览器 stderr、
URL、CDP 事件或模型/网站消息；没有外部网站和凭据。

测试实际断言：

1. checked 真正改变后恢复，而隔离 Mutation 计数为零。
2. 原生 RemoteObject 元数据候选分类接受真实 setter，拒绝伪造 toString 的 JS、
   bound native 和 Proxy。此分类是实验筛选条件，不是已完成的生产身份认证。
3. 隔离 Realm 的原生断点不会误算为覆盖 Main Realm。
4. 主 Realm 直接往返、另一 Realm setter.call、另一 Realm parent.document 查询后
   调用，分别追加两次，均不暂停。
5. 第二元素往返只增加第二元素计数。
6. 页面替换回调被拒绝；以 reset 参数调用仍只能追加。
7. 两个客户端不同恒 false 条件分别生效；移除另一客户端断点后仍记录两次。
