## Phase 0 架构盘点结论

| 能力域 | 改造前现状 | 强依赖问题 | 重构落地路径 |
| --- | --- | --- | --- |
| Browser Runtime | Rust `runtime-supervisor` + `state-collector` + `input-sandbox` 已成熟 | 仅通过 `node-agent` gRPC 暴露，需 Control Plane 驱动 | 由 `crates/lite-server` 直接进程内复用，实现 L0 独立运行 |
| 外部 MCP 接入 | Python `apps/mcp-gateway`（16 工具），转发 Java Control Plane | L0 需额外部署 Python + Java + PG + Redis | L0 内置纯 Rust `/mcp`（收敛 10 工具）+ 纯 Rust STDIO Bridge |
| 托管模型 Worker | 4 个独立 Python 容器（Agent/Reviewer/Outcome/Vision） | 重复 Python 解释器/容器/内存开销 | 新增纯 Rust `crates/worker-supervisor` 单进程多队列并发调度 |
| 镜像构建 | 单一全量镜像（含 Xvfb/x11vnc + OpenCV/Tesseract） | 无头场景白占 ~700MB 镜像与构建时间 | 拆分为 `lite` / `core` / `desktop` / `vision` 四阶段目标 |
| Profile 持久化 | L1/L2 支持 S3 Multipart；L0 初始为整包 `tar.zst` | 每次 Checkpoint 重写全部未变文件 | 升级为文件级内容寻址 Chunk（`chunks/<sha256>.zst`）去重 |
| 背压与调度 | Control Plane 已有自动扩缩与 PSI，瞬时毛刺易触发高压力拒绝 | 缺少 EWMA/P95 分级平滑与 I/O 综合评分 | Rust 侧引入六态 EWMA/P95 分级背压，L2 调度纳入 I/O 综合评分 |
