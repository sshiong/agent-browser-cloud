# 工作区通知可续传 SSE 闭环

> 日期：2026-08-08
> 状态：仓库内实现、Java/Web/OpenAPI/四语言 SDK/N−1 门禁、`make ci`、
> 完整 PostgreSQL/双 Control Plane/Browser Node 集成与对象存储 GameDay 已完成

## 本轮结论

工作区通知中心不再依赖 15 秒固定轮询。Control Plane 新增 Tenant-scoped、Payload-free
的可续传 SSE；Web 与 Tauri 共用 React Query 层收到变化后重新读取正式通知 API。
通知正文、操作者已读状态和 Audit Details 不进入事件流，也没有使用 Mock、
`localStorage` 或前端定时器伪造新通知。

## 服务端闭环

- `GET /api/v1/notifications/event-stream` 接受 `Last-Event-ID`，使用
  `workspace_notifications.audit_sequence_no` 作为单调、不可变的 Tenant 内游标；
- 新连接从当前 Head 开始，断线重连只重放游标之后仍在 90 天保留期内的变化；未来
  Cursor 返回 `notification-stream-reset`，防止客户端永久跳过正式 Feed；
- 数据事件只包含 `sequence`、`occurredAt` 和 `replayed`，收到事件后必须重新读取
  `GET /notifications`；
- 每秒有界读取最多 500 个变化，15 秒 Heartbeat；全局最多 500 个订阅、单 Tenant
  最多 50 个订阅，复用既有 429/503 错误边界；
- PostgreSQL 查询始终包含 Tenant 和保留期过滤，Actor 的已读游标仍只在正式
  `PATCH /notifications/read-cursor` 中修改。

## Web 与 Tauri 共享客户端

- 删除 React Query 的 `refetchInterval: 15_000`；
- 使用 Fetch Streaming 解析分块 SSE，校验 Event ID 与 JSON Sequence 必须一致并严格
  前进；
- 断线保留最近成功 Cursor，按 1—30 秒指数退避重连，浏览器 Offline/Online 事件进入
  `OFFLINE / RECONNECTING / LIVE` 明确状态；
- 初次连接、Reset 和每个变化都会失效正式 Notification Query；窗口聚焦的正常恢复
  读取仍保留，但不再持续轮询；
- 通知抽屉显示 `SSE 实时/连接中/重连中/离线`，重连时明确提示新通知可能短暂延迟，
  不只依赖颜色表达状态。

## 契约与 SDK

- OpenAPI 新增 `streamWorkspaceNotificationChanges`，是滚动兼容的纯新增接口；N−1
  Control Plane 和旧客户端可以忽略；
- TypeScript、Python、Go、Java SDK 已确定性重新生成；当前正式契约为 159 个
  Operation、215 个公开 Schema，TypeScript 为 247 个服务方法；
- 修正三语言 SDK 测试中硬编码的旧 Operation 数量断言，生成清单继续绑定 OpenAPI
  和每个文件 SHA-256。

## 集成回归中修复的状态竞态

完整集成还暴露了 Browser Network Quiet 原始毫秒值持续进入 `contentHash`，导致
Provider Evidence 绑定的权威 State Version 在提交窗口内不断变化。修复后：

- readiness 哈希使用 1 秒粒度并在 Recovery Contract 最大窗口 30 秒处封顶；
- `networkEvidenceFresh=false` 使用独立失败关闭语义，观察器中断仍会立即发布变化；
- 0—30 秒内继续发布足够细的就绪证据，超过最大策略阈值后不再制造无意义版本；
- Provider Evidence 仍严格绑定精确 Context Epoch 与 State Version，没有为通过测试
  放宽安全条件；集成用例在稳定点后再提交真实 Provider Attestation。
