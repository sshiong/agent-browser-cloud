# Recording 最终 JPEG 像素复检与隐私 Gate

> 日期：2026-10-02
> 范围：Recording 本地隐私扫描器、真实 OCR/OpenCV 容器回归、CI。

## 发现与修复

审查用户 11 项目标中的 Recording 治理时发现：扫描器先遮罩像素，再以质量 60 编码
JPEG；OCR 复检已经读取最终 JPEG，但视觉复检仍读取编码前的像素。JPEG 有损编码会
改变像素，因此此前的视觉零残留计数没有证明持久化字节对应的最终像素。

扫描器现在从最终编码缓冲区重新解码图像，要求解码成功且尺寸/通道与遮罩帧一致，再对
该图像执行人脸/二维码复检。OCR、视觉复检、返回的 JPEG 与 SHA-256 均绑定同一组
最终字节。解码失败、尺寸异常或任何残留信号都拒绝该帧，不返回零残留证明。
处理仍在内存内完成，没有新增原始像素、OCR 文本或凭据文件。

修复保持 `tesseract-opencv-pii-face-qr-v2`、既有能力与每帧证明契约，公共 API、迁移、
SDK 和 N−1 格式均不变。它收紧现有证明的正确性，没有增加视觉分类类别。

## 验证

新增 `make test-recording-privacy`，使用与 Browser Node 相同的 Debian/Tesseract/
OpenCV 包。Docker 构建上下文只允许扫描器和测试文件；测试阶段禁用网络并以非 root
身份运行。该 Gate 已接入 `make ci`，普通原生单元测试入口仍独立。

五项回归覆盖：

1. 真实 JPEG 编解码后，视觉复检像素与返回 JPEG 的解码像素精确一致，Hash 对应返回字节；
2. 注入对编码变化敏感的分类结果时，最终像素的残留必须导致拒绝；
3. 有 JPEG 前缀但无法解码的编码输出不能取得零残留证明；
4. 最终图像尺寸异常必须拒绝；
5. 原有真实 Tesseract OCR、OpenCV 二维码检测/遮罩/复检功能自检。

前四项使用确定性合成像素和分类器故障注入，验证持久化边界；第五项使用真实工具。
这些测试没有声明复现真实人脸/二维码在 JPEG 压缩后重新出现，也不替代客户视觉数据集。

- 修复前 **5 项运行、4 项失败**，确认最终像素、残留及解码门禁缺口；真实工具自检通过。
- 修复后 OrbStack 容器内 **5 项全部通过**。
- Session Recorder/Storage Helper Rust 定向回归 **37 项通过、2 项需对象存储环境的测试默认忽略**。
- `make test-upgrade-compatibility`、文档检查 **7 项**、Python 编译与差异空白检查通过。
- 功能提交推送后的 GitHub `ci`/`desktop` 需按精确提交单独核验；上述本机结果不代替远端结果。
