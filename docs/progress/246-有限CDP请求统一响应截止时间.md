# 有限 CDP 请求统一响应截止时间

> 日期：2026-10-02
> 范围：State Collector 与 Session Recorder 的有限 CDP 响应等待。

## 复现与修改

进度 245 已修复导航请求，复查发现十处其他有限请求仍对每条 WebSocket 消息
重新计时：页面 State/Region、资源命令（含带参数版本）、受治理 Evaluate、
Reload、Extension、Viewport、Scroll、通用 Tab/Input/Upload ACK 和 Recorder
控制命令。持续 Ping、无关事件或其他 ID 响应可以延长等待，甚至接受迟到成功。

新增真实 WebSocket 故障注入，直接调用原有状态与资源读取：旧逻辑分别接受约
3.2 秒和 2.4 秒后的成功，超过原三秒和两秒预算，两项回归均失败。Recorder
截图请求回归同样在旧逻辑接受约 5.2 秒后的成功，超过原五秒预算而失败。

现在每个请求在发送命令后只计算一次单调截止时间，循环内读取共用该时间，
读取就绪消息后和接受成功前再次检查，防止缓冲消息优先返回掩盖到期。
各阶段原预算、命令 ID、CDP/异常错误处理和安全围栏保持有效。持续事件订阅
不属于本次有限请求修改；动作确认的一次只读重采继续通过回归。

本次约束响应等待，不证明命令发送、连接、整个动作的总耗时或服务端副作用
已被取消，也不增加输入重放。外部模型的服务端取消与费用停止仍依赖供应商
API/回执。正式 API、Protobuf、数据库和 SDK 没有变更。
