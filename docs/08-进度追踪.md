## 1. 总览

| 阶段 | 状态 | 当前结论 |
|---|---|---|
| Phase 0 合同与工程基础 | 技术项基本完成，待组织签字 | 三语言 Contract 可生成，CI、OpenAPI、JSON Schema、全新库迁移、CP↔Node 烟雾测试已落地；Owner/设计评审签字属于组织 Gate，仓库无法代签 |

## 2. 已验收能力

### Phase 0

- Gradle 8.9 Wrapper、Java 21 Toolchain、Cargo/Pnpm 锁文件和统一 Makefile。
- Protobuf 共 4 个源文件，Buf 可生成 Java、Rust、TypeScript 代码。
- OpenAPI 3.1 与 Error Envelope JSON Schema 可校验。
- GitHub Actions 覆盖格式、静态检查、单元测试、Contract 检查、构建和集成烟雾测试。
- PostgreSQL 17 全新库可由 Flyway 10.22.0 创建并通过 Hibernate Schema Validation。
- PostgreSQL/Redis、Control Plane、Browser Node、Web Console 均有 Dockerfile；Compose 不向宿主暴露 CDP/VNC。
- ADR-001—ADR-006 和开发 Seed 已存在。

### Phase 1 PoC

- Rust Node Agent 提供 `Ping` 与 `Dispatch` gRPC。
- `ChromiumRuntimeSupervisor` 持有 Child 句柄，限制 Session ID 和工作目录，支持启动、停止及 `try_wait` 健康检查。
- Node 拒绝旧 `coordinator_term`，并在进程内对 `message_id` 去重。
- Input Sandbox、State Collector、Network Helper、Storage Helper、Browser Supervisor 已有可编译接口和部分单元测试。

### Phase 2 PoC

- Session/Context/Exclusive Operation V16 核心字段已进入领域模型、Proto、JPA 与 SQL。
- Session 创建支持 PostgreSQL 权威幂等记录；同 Key 同请求返回原资源，不同请求返回 409。
- 列表、详情、启动和终止均执行租户归属校验。
- Session 写路径使用行锁、`context_epoch` CAS 和单 Session Active Operation 唯一索引。
- Coordinator 事务内只写 Node Command Outbox；后台任务通过 gRPC 投递，含超时、退避、最大重试和 Dead Letter 字段。
- Coordinator Ownership 使用 PostgreSQL 条件 Upsert 和心跳续约。
- API 错误不泄露栈信息，并带请求 ID、`no-store` 和基础安全响应头。

## 4. 尚未满足的 Gate

### 生产阻塞项

| ID | 缺口 | 所属阶段 | 验收标准 |
|---|---|---|---|
| SEC-001 | REST API 尚无真实 Bearer/OIDC 认证，`X-Tenant-Id` 只是本地防误读 | Phase 4 | Tenant 必须从已认证 Principal 派生，客户端 Header 不可成为身份来源 |
| SEC-002 | CP↔Node gRPC 为明文且无节点身份校验 | Phase 5 | mTLS、节点证书轮换和授权策略通过验收 |
| REL-001 | Node 去重和最高 Coordinator Term 只存内存 | Phase 1/2 | SQLite Node Journal 重启后仍能去重，并拒绝旧 Term |
| REL-002 | Node 尚未回传 `RuntimeStarted/Stopped/Failed`，Session 会停在 `STARTING` | Phase 1/2 | 命令、事件、状态提交形成端到端闭环 |
| REL-003 | Domain Outbox 尚无消息总线 Publisher/Inbox Consumer | Phase 2/5 | At-least-once 发布、消费去重、重放和 DLQ 演练通过 |
| RUN-001 | 真实 Chromium CDP Readiness、Crash Recovery、资源统计未实现 | Phase 1 | 对真实 Chromium 完成启动、探针、崩溃恢复和资源上限测试 |
| RUN-002 | noVNC/Input Broker/State Collector 仍为接口骨架 | Phase 1/3 | Human Takeover 与 State Resync 用例通过 |
| GOV-001 | 审计写入、保留、Legal Hold 与删除证明闭环未实现 | Phase 5/7 | 对应 V16 治理与运营 Gate 全部通过 |

### 工程改进项

- 为 PostgreSQL Repository、并发 CAS、Outbox 多实例竞争增加 Testcontainers 测试。
- Outbox Dispatcher 增加 `FOR UPDATE SKIP LOCKED` 或显式 Claim，避免多控制面实例重复并行投递。
- 将 Web Console 内联样式迁移到样式表，以便移除 CSP 的 `style-src 'unsafe-inline'`。
- 为容器构建增加 SBOM、签名、镜像扫描和固定 Digest。

## 5. 下一步顺序

1. 完成真实 Chromium + CDP Probe，并由 Node 发回 Runtime 事件。
2. 实现 SQLite Node Journal 和持久化 Inbox/Dedup。
3. 增加 Outbox Claim/Publisher 与故障注入测试，关闭 Phase 1/2 Gate。
4. 进入 Phase 3 前先完成 Profile/Cache 分层 PoC、代理绑定和 Human Takeover 状态重同步。
5. 在任何生产或真实数据接入前完成 SEC-001、SEC-002 和审计闭环。
