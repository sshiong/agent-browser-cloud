> 日期：2026-10-03

## 已复现并修复的窗口

已有 `CancellableHttpClient` 会在租约取消后由 watcher shutdown/close socket，
让正在等待响应的调用醒来。但 DNS/TCP/TLS 连接期间 socket 尚未发布，watcher
仍在等待；连接返回与 watcher 获得调度之间，调用线程可能先发送 POST。
仅在响应返回后检查取消，不能避免这个已明确失去租约的新请求抵达模型供应商。

新增共同的连接 Guard，HTTP 与 HTTPS 均在 connect 前、connect 返回后及每次
send 前检查原请求取消事件。HTTPS 仍使用原 SSLContext/证书校验。连接完成时
取消已成立就抛 `RequestCancelled`，由原 finally 关闭连接；原 watcher 继续负责
已经开始的 socket I/O。没有请求重试、Redirect、Proxy、Cookie 或连接池变化，
Worker Lease/Fencing、Provider URL/Key、响应限制与正式错误码保持原样。

这不是取消信号与 socket.send 的原子事务：最后一次检查与真正发送之间到达的
取消仍由原 watcher 处理。已经进入的系统 DNS/connect/TLS 调用仍可能等到返回，
Guard 只确保返回时已知取消不会继续发新 POST。供应商已经收到的请求，其后台
计算是否停止、是否继续计费仍必须由具体取消协议及计费回执证明。
