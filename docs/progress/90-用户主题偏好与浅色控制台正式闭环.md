# 用户主题偏好与浅色控制台正式闭环

> 日期：2026-07-31
> 数据迁移：V065
> 适用端：Web Console 与 Tauri 2 共享 React UI

## 本轮结论

顶部主题按钮已从禁用占位升级为真实的用户级主题偏好。系统支持跟随操作系统、显式
深色和显式浅色三种模式；偏好由 PostgreSQL 按 Tenant/Actor 持久化，通过正式 API
在 Web 与 Tauri 间共享，不使用 `localStorage`、Fixture 或内存数据伪造保存结果。

浅色模式不是深色反转，而是独立的冷灰蓝纸面 Token。它保留 Neo-Industrial
Observatory 的细边框、网格、紧凑信息密度和状态语义；noVNC 远程桌面画布仍保持受控
黑场，避免改变远端像素内容的观看基准。

## 已完成

### PostgreSQL 与服务端

- V065 新增 `workspace_user_preferences`，以 `tenant_id + actor_id` 为复合主键；
- `theme_mode` 只允许 `SYSTEM / DARK / LIGHT`；
- 无存量回填：不存在数据时返回 `SYSTEM_DEFAULT`，避免扫描外部身份目录；
- 重复写相同模式不更新 `updated_at`、不递增版本，也不生成重复 Audit；
- 实际变更写入 `USER_THEME_UPDATED` Audit，正文只含受控 Theme Mode；
- GET/PUT 均从认证身份派生 Tenant/Actor，普通 Viewer 可修改自身偏好，不能修改他人。

### 正式 API

```text
GET /api/v1/user-preferences
PUT /api/v1/user-preferences
```

PUT 请求：

```json
{
  "themeMode": "LIGHT"
}
```

响应返回模式、来源、更新时间和版本。未知模式由正式 Error Envelope 返回 400。

### Web/Tauri 共享主题层

- `ThemeProvider` 在认证身份建立后读取服务端偏好；
- `SYSTEM` 监听 `prefers-color-scheme`，操作系统切换时即时响应；
- 主题写入使用乐观反馈；请求失败自动回滚到服务端状态并显示 Request ID；
- 顶部菜单支持鼠标、触控和键盘，390px 视口仍保留主题入口；
- 深色和浅色均使用同一业务组件、API Client、Query 与权限逻辑；
- 资源图表的 Grid、Axis、Tooltip 和 Series 已迁移到语义 Token；
- Dark 模式提高 `text-muted` 对比度，Light 模式使用 OKLCH 冷色中性层级与独立语义色。

## 数据流

```text
认证 Tenant/Actor
      │
      ▼
GET User Preferences ── 无数据 ──► SYSTEM
      │
      ▼
ThemeProvider ──► SYSTEM / DARK / LIGHT
      │
      ├─ SYSTEM：监听操作系统外观
      └─ DARK/LIGHT：显式覆盖

用户切换 ──► 乐观呈现 ──► PUT PostgreSQL
                         ├─ 成功：提交版本
                         └─ 失败：回滚 + Request ID
```

## 升级与回滚

V065 是纯增量迁移，旧应用不读取新表仍可运行。升级后第一次访问不写数据库，只有用户
明确切换时才创建记录。应用回滚不会影响 Session、Runtime、Profile 或任何资源控制
数据；再次升级会继续读取原偏好。

若生产回滚需要停用主题 API，应保留表数据，避免用户偏好丢失。正式删除表必须在兼容
窗口结束后的独立 Contract 迁移中执行。
