# Agent Browser Cloud — 进度追踪总览

> 版本：v2.4
> 日期：2026-07-26
> 口径：只把已通过构建、测试或真实运行验收的能力计为“已完成”；仅有类型、页面或接口占位时计为“骨架”。

## 当前结论

| 工作流 | 状态 | 结论 |
|---|---|---|
| Phase 0：工程与契约 | 技术项基本完成，组织 Gate 待签字 | Java/Rust/Web 可构建，Contract、CI、迁移和集成烟雾测试已通过 |
| Phase 1：Browser Runtime | 主链路 PoC 已闭环，容量 Gate 待完成 | Chromium/CDP、State/Input、资源统计、Crash Recovery、Node 重启对账、真实 noVNC、WebSocket 心跳、断线 Key Up Loss 和 HumanTakeover 输入屏障已闭环；资源硬限制与 500 次循环尚未完成 |
| Phase 2：Session Coordinator | PoC 进行中 | 幂等、CAS、Operation、Outbox、Inbox、事件版本校验、在线终态闭环、SQLite Node Journal 和重启后事件重投已落地；多 Coordinator 接管与 Durable Workflow 尚未完成 |
| Web Console 第一阶段 | 端到端切片已完成，仍非生产就绪 | Session、Profile、Proxy 与 Agent 计划审查已连接真实 Control Plane；其余模块仍为开发 Fixture 或待接入状态 |
| Phase 3：Profile、Proxy、State 与 HumanTakeover | 进行中 | Profile 技术 MVP/恢复 PoC、Proxy 技术 MVP、State Diff/Full Resync、HumanTakeover 与真实 noVNC 已闭环；业务恢复验证器、原生 Region Resync 与流式 State 尚未完成 |
| Phase 4：Agent 基础与安全边界 | 进行中，安全计划与只读执行已闭环 | 单一受限 Planner、Intent/Plan Gate、Prompt Injection 隔离、Capability Token、只读 Executor/Tool Result Validation 和真实 UI 已闭环；Navigate/Target Input、确认与有限 Replan 尚未实现 |
| Phase 5—7 | 未开始 | 只有设计文档和少量领域骨架，不宣称实现 |

当前代码适合本地开发与 PoC 验证，不能处理真实客户数据，也没有通过 V16 生产发布 Gate。

  `displayName`、`profileId`、`region`、`resourceClass`，不向客户端暴露任意 metadata。
- 环境列表和详情页改为展示真实名称、Profile、区域、资源等级、Runtime 与 Node；
  已有 Session 没有合法 `displayName` 时安全回退到 Session ID。
- 增加 Java 应用服务契约测试，并在真实集成测试中验证新增字段的数据库到 API 闭环。
- 新增 `NodeEventService.Publish` Protobuf/gRPC 契约及 Java、Rust、TypeScript 生成物。
- Browser Node 回传 `RuntimeStarted/RuntimeStopped`，发送失败时通过重复命令重投进程内结果。
- Control Plane 在事务内完成 Event Inbox 去重、Tenant/Term/Epoch/Sequence 校验、
  Session Context/State 提交与 Operation Commit。
- 集成测试已验证 Start/Terminate 两个 Operation 均进入 `COMMITTED`，两个事件进入 Inbox。
- 真实浏览器测试已改为等待“运行中/已终止”终态，不再只验证活跃 Operation。
- Runtime 启动现在必须通过 `/json/version` CDP Readiness，健康检查同时验证进程与 CDP。
- 新增真实 CDP State Collector，通过 WebSocket 采集 URL、Title、交互目标、角色、
  可见性、坐标、State Version 与内容哈希，并限制 CDP 仅可使用 Node 回环地址。
- 使用真实 Chromium 验证页面导航、按钮/输入框状态采集、Runtime 启停、CDP 健康与
  CPU/内存采样。
- 新增 SQLite Node Journal，持久化命令结果、Coordinator Term、Event Sequence 与
  待确认 Node Event。
- Node 重启后会扫描 Journal 并自动重投事件；测试验证 Journal 关闭/重开后事件仍可
  被 Control Plane gRPC 接收并标记已送达。
- Runtime 主动健康监控在浏览器进程退出时持久化并发布 `BrowserCrashed`，失败事件进入
  同一 Journal 重投链路。
- Input Sandbox 新增真实 CDP 键盘、鼠标执行器，按单 Session 序列化输入，
  拒绝陈旧 sequence、幂等处理重复 sequence，并在 Stop 时执行 All-keys-up /
  All-buttons-up。
- Node Runtime Monitor 已接入输入释放看门狗：输入通道超过 5 秒无活动但账本仍有
  按键、按钮或拖拽状态时，主动向 Chromium 发送释放事件；中键/右键 CDP 位掩码和
  Enter、Tab、Escape、删除键、方向键映射均有回归覆盖。
- 新增 `ExecuteInputCommand`、`BrowserStateEvent` 和交互目标 Protobuf 契约及三语言生成物。
- Browser Node 周期采集页面状态，内容哈希变化时持久化事件到 SQLite Journal 并上报；
  Control Plane 完成版本校验、JSONB 最新状态存储和租户隔离的
  `GET /api/v1/sessions/{sessionId}/state`。
- Session 详情页已接入真实 Browser State，展示 URL、标题、质量、版本、哈希、坐标与
  可见/可用标志；运行期间每 2 秒刷新，204 时明确显示尚未采集而不伪造数据。
- 集成烟雾测试现验证 Browser State 从假 Chromium CDP WebSocket 经 Node Event、
  Inbox、PostgreSQL 到 REST API 的完整链路。
- Coordinator 收到 `BrowserCrashed` 后会抢占活跃写操作，创建优先级 95 的
  `RECOVERY` 排他 Operation，重启同一 Runtime Build，并在 `RuntimeStarted`
  返回后递增 Context Epoch/Browser Generation、提交 Operation 和恢复 `RUNNING`。
- Recovery 采用一小时最多三次的持久 Operation 计数熔断；超过预算或缺少 Runtime
  Build 时进入 `FAILED`，避免无限重启。
- Node Journal 新增 Runtime Lease，持久化 Tenant、Term、Context、Generation、
  PID 与进程启动身份。Node 重启会校验 PID 身份、清理遗留进程、恢复 Generation
  下界并发布 Crash Recovery Event。
- Start/Stop 命令结果、待投事件与 Runtime Lease 转换在同一 SQLite Immediate
  Transaction 中提交，关闭“Runtime 已启动但 Lease/Event 尚未落盘”的崩溃窗口。
- 修复 State Content Hash 将版本化 `target_ref` 纳入哈希导致静态页面重复上报的问题；
  相同页面的 State Version 可递增，但 Content Hash 保持稳定。
- 集成测试实际强杀 Chromium 后验证自动恢复到 Epoch 2，再重启 Browser Node 验证
  Runtime Lease 对账和恢复到 Epoch 3，最后正常终止。
- 新增正式 `BeginHumanTakeover` / `EndHumanTakeover` Command 与
  `HumanTakeoverReady` / `HumanTakeoverEnded` Event，三语言 Contract 与 OpenAPI
  同步生成。
- HumanTakeover 以优先级 90 的排他 Operation 抢占低优先级可抢占操作；Node 在接管开始
  和结束时强制 All-keys-up / All-buttons-up，并把即时 Browser State 作为 Ready/Ended
  Event 一并提交。
- Control Plane 只在 Ready Event 后进入 `EXECUTING`，只在 Ended Event 携带 State
  Resync 后提交 Operation；错误 Actor、过期 Epoch、缺失 State 的 Event 均被拒绝。
- Web Console Session 详情接入真实人工接管 Mutation，远程桌面工作区展示 Operation、
  Actor、State 与输入安全状态；只有持有 Operation 的 Actor 可以打开和释放接管。
- 集成测试与真实浏览器 E2E 已验证 HumanTakeover
  `PREPARING → EXECUTING → COMPLETING → COMMITTED` 全链路。
- 新增 Rust `remote-desktop-gateway`：只代理二进制 RFB，VNC TCP 仅注册回环地址；
  HMAC Ticket 绑定 Tenant、Actor、Coordinator Term、Context/Operation Epoch，限制
  120 秒寿命、一次性 Nonce、Origin 白名单和单 Session 单客户端。
- Browser Node 已托管 Xvfb/x11vnc 图形 Runtime，WebSocket 数据面具备 Ping/Pong
  半开连接检测和两秒重连宽限；生产环境拒绝默认 Ticket Secret 和空 Origin 白名单。
- Gateway 断线不依赖前端回调：Node 强制执行 CDP 与 x11vnc All-keys-up /
  All-buttons-up，重采集 Browser State，并把带 `GATEWAY_DISCONNECT` 原因的
  `HumanTakeoverEnded` 持久事件提交给 Control Plane。
- Web Console 已使用正式 `@novnc/novnc` RFB Client 和一次性 Ticket API 展示实时
  Canvas，并明确呈现连接协商、实时、断线与失败状态。
- 真实浏览器 E2E 已验证 320×200 像素帧、鼠标、键盘、显式释放、页面离开后的服务端
  Operation 回收，以及只发送 Shift KeyDown、不发送 KeyUp 时的 x11 清键屏障。
- 依赖审计发现新披露的 React Router RSC Action CSRF 与工具链
  `brace-expansion` DoS 后，已迁移至 `react-router 8.3.0` / React 19.2.8 并锁定
  `brace-expansion 5.0.8`；高危依赖审计重新返回无已知漏洞。
- Profile Core/Ephemeral 已分盘，活跃 Profile 实施单 Writer 与 Write Epoch；
  Runtime 停止后通过 Manifest、SHA-256 和 Commit Marker 原子提交检查点。
- Restore 会校验 Manifest 身份、文件路径/数量/大小/哈希与 Marker；损坏检查点测试确认
  不会误报成功，同一 Session 的 Node 重启会复用未检查点工作区。
- Control Plane 新增 Profile Create/List/Get API、V003 元数据迁移和 Session/Profile
  绑定校验；Web Console Profile 页面已删除 Fixture，接入真实创建、查询、搜索和响应式状态 UI。
- 集成测试验证 Session A 经 Crash/Node 重启后提交 Epoch 1，Session B 恢复同一
  Profile 后持久计数到 4 并提交 Epoch 2；跨租户 Profile 访问返回 403。
- 新增 V004 Proxy Allocation 持久化、Static Provider 服务和租户隔离的
  `GET /api/v1/proxies`；Session 启动前绑定 Proxy，并同步递增 Context Epoch 与
  Network Revision。
- Browser Node 新增 Static HTTP Proxy bind/verify/release、本地 Circuit Breaker
  和严格 Endpoint 校验；出口验证失败时不启动 Chromium，也不回退直连。
- Chromium Runtime 强制注入 Proxy Server 与 Loopback Bypass 参数；
  `RuntimeStartedEvent` 回传 Binding、Exit IP、Country 和 ASN，Control Plane
  核对后提交 `BOUND`，终止后提交 `RELEASED`。
- 生产环境同时在 Control Plane 和 Browser Node 拒绝直连开关；Docker Compose
  仅以显式 local override 保留无 Proxy 的开发路径。
- Proxy 页面已删除 Fixture，展示真实 Provider 状态、Allocation 账本、观察出口、
  验证时间和 Direct Fallback 策略，并具备响应式 Loading/Empty/Error 状态。
- 集成测试与 Web E2E 已验证出口 `203.0.113.10`、运行中 `BOUND`、直连
  `DENIED` 和终止 `RELEASED`；基础设施级出口防逃逸仍列为生产阻塞项。
- State Collector 改用稳定 DOM 路径 Target Ref，普通内容变化不再使全部 Target
  随 State Version 失效；导航和显式 Resync 才递增 Target Revision。
- 新增有界 `BrowserStateDiff`、`DiffTruncated` 与 `RequestStateResync` Protobuf；
  Diff 超过 60,000 字节或目标变化预算时显式截断并冻结增量链。
- Control Plane 只在 Base State Version 精确匹配时应用 Diff；Gap/Truncated 会将
  Current State 标记 `INVALID` 并通过 Outbox 自动请求 Full Resync。
- 新增租户隔离、运行态 Gate 和 PostgreSQL 幂等的
  `POST /sessions/{id}:resync-state`；Current State 在新 Full Snapshot 提交前保持
  `RESYNCING`。
- Session 详情新增 Full/Region Resync 控件；Region 请求当前显式使用
  `REGION_RESYNC_FULL_FALLBACK`，原生区域裁剪仍列为未完成。
- 集成测试验证 Full v1 → Diff v2 → `RESYNCING` → Full Resync v3/`COMPLETE`；
  Web E2E 已通过真实页面发起 Full Resync。
- 新增 V005 `agent_tasks` 持久化及租户隔离的 Agent Task Create/Get/List API；
  幂等创建同时保存受限 Plan 与脱敏后的 Prompt Security Evidence。
- 单一规则 Planner 当前只生成 `navigate`、`get_current_state`、`get_url` 和
  `get_page_summary` 计划；Session 运行态、State Quality、动作上限、计划过期、
  Replan Budget 与精确域名白名单均进入 Plan Validator。
- Intent Guard 拒绝 Cookie/Password/OTP/Shell/Raw CDP/Vault/Kubernetes/Node Helper
  等越权目标；高风险财务/账号目标进入确认需求，但因确认闭环尚未实现而安全阻断。
- 外部网页、邮件、文档与第三方内容默认 `UNTRUSTED` 且不可执行；调用方伪造
  System/Platform Policy 来源会被拒绝，Indirect Prompt Injection 只记录 Hash、
  Taint 与规则命中，不持久化原始正文。
- Agent Goal 入库前执行 Password/Cookie/OTP、Email 和 Phone 基础脱敏；
  API View 不返回签名 Capability Bearer，只暴露不可用作调用的 Token ID。
- HMAC Capability Token 已绑定 Tenant、Session、Intent、Plan Operation、Tool、
  Action、Domain、Data Scope、Risk、Expiry 与单次调用预算；生产环境拒绝默认 Secret。
- Automation 页面已删除 Fixture，连接真实任务 API，展示 Plan/Blocked、风险、
  Capability Handle、验证规则和 Prompt Security Event，并明确标注 Executor 尚未接入。
- 集成测试已验证 V005 迁移、计划幂等、域名越权阻断、Injection 隔离、Bearer 不泄露
  与租户列表；Web E2E 已通过真实 UI 创建计划并观察安全事件。
- 新增 V006 Tool Capability 单次使用账本和 Agent Task 执行结果字段；任务支持
  `PLANNED → RUNNING → COMPLETED/FAILED`，并绑定 `AGENT_INTERACTIVE` 排他 Operation。
- 单 Executor 已真实执行 `get_current_state`、`get_url`、`get_page_summary`；
  每一步在 Tool Service 重新验签，并原子消费 Token，重复 Token 会被拒绝。
- 只读 Tool 强制校验 Tenant、Session、Context Epoch、State Quality 和当前域名；
  URL 输出移除 UserInfo/Query/Fragment，页面摘要限制目标数并执行 Email/Phone Mask。
- Tool Result 保存结构化 Output、SHA-256、Verification 和完成时间；全部 Step 验证后
  才提交 Operation 和 Task，失败则中止 Operation 并保留已完成证据与安全错误码。
- Automation 页面可执行不含 Navigate 的只读计划，显示 Completed/Verified 和实际
  Tool Output；含 Navigate 的计划明确显示等待 Node Executor。
- 集成测试验证三枚 Capability 恰好消费一次、Agent Operation `COMMITTED`、
  Idempotent Replay 与三个 Verified Result；真实 Web E2E 已通过 UI 执行并展示证据。

## 本轮验收证据

已通过：

```bash
pnpm --dir apps/web-console build
pnpm --dir apps/web-console lint
pnpm --dir apps/web-console test
pnpm --registry=https://registry.npmjs.org --dir apps/web-console audit --audit-level high
make contracts-check
make test-integration
make test-e2e  # 自动托管 PostgreSQL、Redis、Browser Node、Control Plane 与 Vite
REAL_CHROMIUM_PATH=... cargo test -p runtime-supervisor starts_probes_and_stops_real_chromium -- --ignored
REAL_CHROMIUM_PATH=... cargo test -p state-collector collects_state_from_real_chromium -- --ignored
```

依赖审计结果：`No known vulnerabilities found`。

真实浏览器流程覆盖：

1. 从 Control Plane 加载 Session 列表；
2. 创建第一个 Session 并进入详情；
3. 发起 Start Operation 并自动进入“运行中”；
4. 获取 HumanTakeover、进入远程桌面控制工作区并观察 `CONTROL ACQUIRED`；
5. 等待真实 RFB 像素帧并验证鼠标、键盘输入抵达 VNC Server；
6. 结束接管，等待输入释放和 State Resync 后观察 `NO CONTROL`；
7. 再次接管后仅发送 Shift KeyDown，直接离开页面，验证服务端清键并回收 Operation；
8. 终止运行中的 Session，提交 Profile Checkpoint Epoch 1；
9. 在 Browser State 面板发起 Full Resync，并验证后端返回 `QUEUED`；
10. 打开真实 Proxy 页面，验证 Provider `CONFIGURED`、Allocation `BOUND`、
   出口 IP 与 Direct Fallback `DENIED`；
11. 打开真实 Profile 页面并通过创建对话框创建 Profile；
12. 创建第二个从未启动的 Session 并完成空终止，不伪造检查点；
13. 打开真实 Agent 任务页面，从运行中 Session 创建受限只读计划，验证
    `PROMPT_INJECTION_DETECTED` 隔离事件；
14. 通过 UI 执行三个只读 Tool，验证 `COMPLETED`、`VERIFIED` 与脱敏结果；
15. 页面无浏览器控制台错误。
