# 租户审计链可续传 SSE 与审计轮询移除

> 日期：2026-08-13
> 状态：审计全量列表已由租户审计链游标无损驱动，固定轮询移除；Nodes 与
> Enterprise 总览轮询仍未关闭

## 本轮目标

关闭[进度 142](142-SecureDebug通知准入修复与轮询替换边界.md)记录的第一项遗留：
安全中心的审计全量列表当时只能降为 30 秒兜底轮询，因为现有 Overview 与
Notification 两条流都只覆盖高信号子集，漏事件即永不刷新。

## 已完成

### 事件源

`audit_events` 自 V010 起就有 `uq_audit_events_tenant_sequence`，即每租户单调、
不可变的防篡改链序号。**每一条**被审计的行都会推进它，因此它是审计列表唯一
无损的游标，不需要新增表或迁移。

- 新增 `AuditEventStreamStore`：按租户读 `sequence_no` 与 `created_at`，
  显式排除 V010 之前 `sequence_no IS NULL` 的历史行——它们早于链，永远不会推进
  活跃游标；
- 新增 `AuditEventStreamService`：与既有 Resource/Overview/Notification 三条流
  保持同一实现约定，含 `Last-Event-ID` 续传、超前游标 reset、`replayed` 标记、
  每租户与全局订阅上限、1 秒批量发布、15 秒 keepalive 和失败即关闭；
- `AuditController` 新增 `GET /api/v1/audit-events/event-stream`，沿用类级
  `@PreAuthorize(SECURITY_ADMIN)`，租户来自认证身份而非请求参数。

事件体是 payload-free 的 `{sequence, occurredAt, replayed}`，不携带任何审计
内容，客户端凭游标回读自己有权访问的投影。

### 契约与 SDK

- OpenAPI 新增 `streamAuditEventChanges`，与 Overview/Notification 流同构；
- 四语言 SDK 重新生成：202 Operations / 271 Schemas（此前 201/271），
  TypeScript 329 service methods / 35 services，manifest 与哈希同步；
- `Makefile` 中过期的 “200 operations, 269 public schemas” 注释更正为当前值。

### Web Console

- `useAuditEventStream` 跟随审计链游标，在 `ready`/`change` 时失效
  `platformKeys.auditEvents`，具备离线、指数退避重连与 `Last-Event-ID` 续传；
- `useAuditEvents` 移除 `refetchInterval`，安全中心不再有任何固定轮询；
- 审计面板新增流状态标签（待连接/连接中/实时/重连中/离线），手动刷新保留；
- `platform.ts` 把身份与角色头提取为 `roleHeaders`，列表请求与 SSE 共用同一
  本地开发身份边界，避免两处漂移。

- Java：从不可变链游标续传、新订阅者不重放历史、多租户游标互不串读、超前游标
  reset 与每租户订阅上限；
