## 资源策略更新竞争

GitHub `a055d41` 的 CI `33719726436` 捕获资源策略 PATCH 在提交时抛出
`ObjectOptimisticLockingFailureException`：后台资源决策与用户修改共享
`session_resource_policies.version`。用户更新现在以 Tenant/Session 精确条件先取得
PESSIMISTIC_WRITE 行锁，再读取、校验权限、申领幂等键及更新；保留版本字段。

新增隔离集成用例持有未提交的版本更新，通过 PostgreSQL 实际锁等待图确认 HTTP 请求
发生等待，然后释放事务，检查契约 HTTP 202、COMMITTED、同幂等键返回同 Operation，
以及 POLICY_UPDATED 仅一条。用例只接受 smoke 专用容器名称，在启动该测试 Session
之前执行，避免后台采样被误认为目标 HTTP 请求。首轮断言误用 HTTP 200，已按正式契约
修正为 202；修正后已输出 `resource_policy_concurrent_patch=true`。该轮后续运行被并行
bootJar 覆盖运行制品影响，出现延迟类加载失败，已结束并清理。smoke 现在启动时复制
独立 JAR，所有控制面启动/重启均使用该副本；最终代码完整集成已通过，输出
`resource_policy_concurrent_patch=true`、`audit_chain_valid=true`，Audit 346 条。

该改动解决用户 PATCH 读取过期版本的竞争；不代表所有后台写入竞争或多表锁顺序已经
全面审计。现有后台事务的乐观版本保护继续生效。

## Vision Worker HTTP 失败处理

检查真实 Worker 启动链时发现 Vision Worker 把 `retryable` 作为位置参数传给仅允许关键字
参数的 `WorkerError`，控制面返回任何 HTTP 4xx/5xx 时会变成 `TypeError`。现改为关键字参数；
新增真实 loopback HTTP fixture，覆盖 401/403/409 为不可重试、500/503 为可重试，并保留
服务端错误码。Agent/Reviewer/Vision Worker 共 22 项测试通过。
