## 按阶段列出的剩余项

### Phase 0：工程和契约

1. 核心模块 Primary/Secondary Owner、RACI、Threat Review 和发布审批签字；
2. 在正式 Release Pipeline 中以本轮 N/N-1、回滚、契约和迁移 Gate 阻断发布；
3. 对真实 Staging 制品完成下载后验签、升级、回滚和证据归档。

### Phase 1：Browser Runtime

1. 目标 Linux 节点的委派 Cgroup v2、OOM/PSI、Xvfb/x11vnc 并发长稳；
2. Renderer/Browser/Node 组合故障、磁盘/网络预算和多 Node 容量证书；
3. 独立 GPU Helper、硬件编解码和 GPU/Media 隔离证书。

本机真实 Chrome 已完成 500 次顺序生命周期和 500 次、并发 4 的 Browser Density
证书；这些证据不替代目标 Linux/目标云验收。

### Phase 2：Session Coordinator

1. 双 Coordinator 长稳下的数据库延迟、连接池拥塞和时钟偏差；
2. Hot Tenant 跨 Shard 安全点迁移、旧 Route Epoch 拒绝和压力测试；
3. Session Ownership 批量投影与列表查询的 N+1 优化；
4. 目标 Prometheus/Alertmanager/Pager 的跨 Pod 聚合、告警到达和关闭演练。

### Web Console

1. Groups 正式领域模型/API/UI，以及全局搜索、通知、主题和用户菜单；
2. Environment/Profile Import、Saved View、可复用 Proxy Binding 和环境更多操作 API；
3. Runtime Build/Agent Policy 的一等创建契约，以及列表
   Group/Tags/Agent/Extension 受控投影；Execution Environment 和 AUTO Resource
   Policy 已是一等契约，Resource Template 只保留为后端内部调度实现；
4. Resource/Migration 已完成 PostgreSQL SSE、断线重连和序列校验；仍缺 State/Audit
   统一事件层、跨 Region Event Bus 和对应轮询替换；
5. 从 OpenAPI 自动生成并发布 TypeScript Client；当前四 SDK 为手写、契约测试型 SDK；
6. 真实企业 IdP 的 Metadata、Claim、MFA/ACR、Logout 和租户映射联调；
7. Browser Node 的 CPU/内存/PSI/Input Ledger 5 秒采集、同节点 Cgroup Actuator、
   Safe Point、自动休眠、严格终止和持久跨 Node 迁移核心链已完成；仍缺完整
   Browser/Agent/State/Extension/Media 指标、业务事务信号 Producer、真实双 Node
   E2E 和应用专用 Business Recovery Validator；
8. Tauri 2 桌面容器、安全存储、签名发布，以及桌面视觉回归、全键盘、屏幕阅读器和
   目标浏览器矩阵。

环境页分层、独立空状态、服务端搜索、六步 AUTO 创建、Resource Policy/Placement/
Event 详情、基础 5 秒真实遥测、同节点在线扩缩容、Nodes、Extensions、Enterprise
Operations、OIDC/RBAC 与 Viewer/移动端 E2E 已接真实 API，不再属于未实现项。

### Phase 3：Profile、Proxy、State 与 HumanTakeover

1. 默认 `Login Required`/`Business Ready` Validator 已完成；仍缺 Application-aware
   Validator/Profile Adapter 和业务恢复规则 DSL；
2. S3 Archive 校验恢复核心链已完成；仍缺 Warm Tier Delta Journal、跨 Region
   Restore、KMS 和真实 IAM；
3. 基础设施出口防逃逸、真实 Proxy Provider、短期 Secret、DNS/Provider 故障；
4. 原生 Region Resync、Chunk/Checksum/Commit、流式 Snapshot、Backpressure 和熔断；
5. 目标云单向网络分区、丢包和多客户端竞争矩阵。

### Phase 4：Agent 生产增强

MVP Gate 和 Production-like 授权 Replay 已闭环，仍缺：

1. Network/Toast/Dialog/Visual/Login/Business Entity Validator 与组合 DSL；
2. 独立无宿主权限 Agent Worker Sandbox、固定 IPC 和单独故障域；
3. Reviewer Agent、真实模型 Provider/模型治理和大规模 Replay Matrix；
4. Challenge Detection、一次性 HumanAssist、协作取消和跨 Region Workflow；
5. 完整 State 分类、截图敏感区模糊和 Purpose 绑定访问控制。

### Phase 5：可靠性、安全与审计

Legal Hold、删除 Receipt、License Inventory 和签名 Audit Export 已完成。仍缺：

1. GPU Helper、AppArmor/SELinux/Landlock 强制策略和真实集群跨 UID 验收；
2. 独立 Secure Debug Worker、像素级强制录像和 WORM Recording Manifest；
3. Offline Root/HSM、OCI Admission 强制验签、撤销和生产回滚；
4. 在线信任根双写、CRL/SPIFFE 撤销与过期证书演练；
5. 目标云 Object Storage/KMS/IAM、Multipart Resume、跨 Region Restore；
6. 目标云 Ingress/CNI 单向网络分区及 Provider 故障矩阵。

### Phase 6：密度与 Kubernetes

并发 Browser Density、Extension 自适应采样、PSI 有界驱逐、Media 独立容量、
多 Node 精确路由单测以及 N/N-1 Kind 滚动/回滚已完成。仍缺：

1. PostgreSQL/gRPC/GC 长稳的端到端 Coordinator 容量证书；
2. 双 Coordinator Hot Tenant/Shard 迁移压测；
3. 目标云多节点 CNI 防直连、CSI Snapshot、Kata RuntimeClass 和 Browser Node Pool；
4. Operator Watch/Informer、API Server/etcd 故障长稳和指标告警；
5. 目标 Linux 多 Browser Node 的压力驱逐、Media/GPU 和长期密度证书。

### Phase 7：企业运营

已完成 Validation Farm 数据/证据闭环、授权 Replay、Compatibility Gate、版本化费率与
成本解释、Cost-aware Placement、SLO/Error Budget、SLA Exclusion、Retention/Legal
Hold/删除 Receipt、Residency Admission、Compliance、License Inventory、签名 Audit
Export、Recovery GameDay 证据、Region/DR Registry、Media、Terraform Module、四语言
SDK 和企业运营 UI。仍缺：

1. 隔离 Validation Worker 的队列编排、自动浏览器版本矩阵和大规模业务页面回归；
2. Burn Rate 自动发布冻结及 GameDay 失败联动发布系统；
3. 真实跨 Region Authority、数据库/对象复制、流量切换和 RTO/RPO 演练；
4. Terraform Provider；当前交付的是可验证 AWS 基础设施 Module；
5. 自动生成、版本发布、签名和兼容策略完整的正式 SDK Distribution；
6. 目标云 KMS/HSM 签名 Audit Export；本地验收使用可替换的 HMAC Key。

## 下一步优先级

1. 先关闭目标 Linux/目标云安全与容量 Gate；
2. 建设 Business Recovery Validator 和跨 Region State/Profile；
3. 完成 Hot Tenant、State/Audit 统一事件和 Operator Watch/Informer；
4. 把 Validation、Burn Rate、GameDay 接入真实发布系统；
5. 完成真实多 Region、Terraform Provider、正式 SDK 发布和组织签字。
