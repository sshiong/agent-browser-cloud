# 工作区通知中心正式闭环

> 日期：2026-07-31
> 数据迁移：V064
> 适用端：Web Console 与 Tauri 2 共享 React UI

## 本轮结论

顶部通知按钮已从禁用占位升级为真实工作区通知中心。通知由 PostgreSQL 不可变审计事件
在同一事务内投影生成，经正式 Control Plane API 返回；已读状态按 Tenant 和 Actor
独立持久化。前端不使用 Mock、`localStorage`、JSON 文件或内存状态伪造通知。

该闭环覆盖仓库内的通知数据模型、租户隔离、API、RBAC、Web/Tauri 共享 UI、视觉与
完整集成验收。它不等同于跨 Region 消息总线、浏览器系统通知或移动推送；这些仍属于
后续生产深度工作。

## 已完成

### PostgreSQL 权威数据

- 新增 `workspace_notifications`，只保存高信号 Audit 投影，不复制敏感正文；
- 通知 ID 可直接关联来源 Audit Event，Tenant 内以 `audit_sequence_no` 唯一；
- 覆盖安全、资源、Agent、发布和系统五类事件，以及 INFO/WARNING/CRITICAL 明确等级；
- 新增 `workspace_notification_read_cursors`，以 `tenant_id + actor_id` 保存单调递增
  已读游标，阻断跨租户和跨操作者已读状态串扰；
- 通知默认保留 90 天，服务端定时清理每批最多 5,000 条，避免无界删除；
- V064 只对部署后的新 Audit Event 建立投影，不扫描、回填历史审计账本，保持升级
  有界并兼容 N−1 应用。

### 正式 API 与服务端约束

- `GET /api/v1/notifications`：最多 50 条、基于 Audit Sequence 的游标分页；
- `PATCH /api/v1/notifications/read-cursor`：按当前身份更新已读位置；
- Tenant 和 Actor 均由认证身份派生，不接受客户端覆盖；
- 已读游标只允许单调前进，未来游标返回 400，不允许把尚不存在的通知标记为已读；
- 返回未读数、Feed Head、下一页游标、Request ID 和资源跳转信息；
- 访问受既有 `READ` 权限和平台身份边界保护。

### Web 与桌面共享 UI

- `TopContextBar` 的禁用铃铛已替换为 `WorkspaceNotificationCenter`；
- 支持未读数量、分类和严重度、全部已读、游标翻页、资源详情跳转和 15 秒真实 API
  刷新；
- 网络断开时明确提示数据可能过期，读取失败显示服务端 Request ID；
- 状态同时使用文字、图标和视觉层级表达，不只依赖颜色；
- 390px 窄屏使用全宽侧栏，主要交互具备适合触控的命中区；
- 组件、API Client、Query 和权限逻辑由 Web/Tauri 共用，不新增桌面专用业务分叉。

## 数据流与安全边界

```text
业务事务写入 Audit Event
        │ 同一 PostgreSQL 事务
        ▼
V064 Trigger 选择高信号事件并写入通知投影
        │
        ▼
Control Plane 按认证 Tenant/Actor 有界读取
        │
        ▼
Web / Tauri 共享通知面板

已读操作：认证 Actor → 单调 Read Cursor → PostgreSQL
```

通知正文只由服务端根据受控事件字段生成。Secret、Credential、签名 URL、Audit
Detail 正文和直接个人联系/支付信息不会进入通知表或前端响应。

## 迁移与回滚

V064 是纯增量迁移，不改变既有 Audit 写入契约。旧应用版本不需要识别新表即可继续
运行。若应用回滚到 N−1，Trigger 仍会持续生成通知；再次升级后可继续按 Sequence
读取，不丢失部署后的高信号事件。

生产回滚若需要停用投影，应先禁用 Trigger，再保留两张表完成证据审计；不应直接删除
通知和已读数据。正式生产环境仍需按发布流程完成备份、迁移时延观察和回滚演练。
