## 1. 设计原则

### 1.1 数据权威性

| 数据类型 | 存储位置 | 说明 |
|---------|---------|------|
| 权威数据 | PostgreSQL | Session Identity、Context Commit、Coordinator Ownership、Operation、Workflow 等 |
| 节点日志 | Browser Node Journal | 实际 Runtime PID、最后执行的 Operation、Profile Write Epoch 等 |
| Profile 标记 | Commit Marker | Checkpoint 已完整提交证明 |
| 密钥 | KMS/Vault | Key Version、Key State、Rotation/Revocation |
| 派生数据 | Redis/内存 | Cache、Current State View、Metrics 等；权威 Tenant/Session Route 必须在 PostgreSQL |

### 1.2 写操作统一路径

```
Command
→ Session Coordinator
→ Exclusive Operation
→ PostgreSQL 事务（Operation + Context + Outbox）
→ Browser Node / Workflow
→ Result Event
→ State Commit
```

### 1.3 禁止事项

- Redis 成为唯一事实来源
- Browser Node 直接写控制面业务表
- 每个模块自行创建分布式锁

---

## 2. 数据库选型

| 组件 | 选型 | 版本 | 用途 |
|------|------|------|------|
| 主数据库 | PostgreSQL | 17 | 权威状态存储 |
| 缓存 | Redis | 7 | 缓存、路由、短期状态 |
| 节点日志 | SQLite (MVP) | - | Browser Node Journal |
| Profile 存储 | NVMe + Warm Tier + Object Storage | - | 分层存储 |

## 3. 表结构设计

### 3.1 sessions — Session 主表

```sql
-- V001__initial_control_plane.sql

CREATE TABLE sessions (
    id                  TEXT PRIMARY KEY,
    tenant_id           TEXT NOT NULL,
    profile_id          TEXT NOT NULL,
    region              TEXT NOT NULL,
    resource_class      TEXT NOT NULL DEFAULT 'L2',
    state               TEXT NOT NULL DEFAULT 'CREATED',
    policy_hash         TEXT NOT NULL DEFAULT '',
    metadata            JSONB DEFAULT '{}',
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    terminated_at       TIMESTAMPTZ
);

-- 索引
CREATE INDEX idx_sessions_tenant_id ON sessions(tenant_id);
CREATE INDEX idx_sessions_state ON sessions(state);
CREATE INDEX idx_sessions_created_at ON sessions(created_at);

-- 租户隔离的复合索引
CREATE INDEX idx_sessions_tenant_state ON sessions(tenant_id, state);
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | TEXT | PK | Session ID，格式 `ses_` + 随机字符串 |
| tenant_id | TEXT | Y | 租户 ID |
| profile_id | TEXT | Y | Profile ID |
| region | TEXT | Y | 部署区域 |
| resource_class | TEXT | Y | 资源等级：L0-L5 |
| state | TEXT | Y | 状态：CREATED/STARTING/RUNNING/.../FAILED |
| policy_hash | TEXT | Y | 策略哈希 |
| metadata | JSONB | N | 扩展元数据 |
| created_at | TIMESTAMPTZ | Y | 创建时间 |
| updated_at | TIMESTAMPTZ | Y | 更新时间 |
| terminated_at | TIMESTAMPTZ | N | 终止时间 |

### 3.3.1 Hot Tenant 权威路由表

V040 新增 `coordinator_tenant_routes`、`coordinator_session_routes` 和
`coordinator_route_migrations`。Tenant 表保存当前/待提交分区数与单调 Route Epoch；
Session 表保存当前逻辑分区和 Shard；Migration 表保存增量安全点迁移进度、Actor、
Request ID 与结果。新列和新表均为增量扩展，N-1 ownership 写入通过
`route_epoch DEFAULT 1` 继续兼容。

### 3.4 exclusive_operations — 排他操作表

```sql
CREATE TABLE exclusive_operations (
    operation_id        TEXT PRIMARY KEY,
    session_id          TEXT NOT NULL REFERENCES sessions(id),
    owner_type          TEXT NOT NULL,
    actor_id            TEXT,
    mode                TEXT NOT NULL,
    priority            INTEGER NOT NULL DEFAULT 0,
    operation_epoch     BIGINT NOT NULL,
    coordinator_term    BIGINT NOT NULL,
    context_epoch       BIGINT NOT NULL,
    workflow_id         TEXT,
    cancellable         BOOLEAN NOT NULL DEFAULT TRUE,
    preemptible         BOOLEAN NOT NULL DEFAULT FALSE,
    phase               TEXT NOT NULL,
    state               TEXT NOT NULL DEFAULT 'ACTIVE',
    deadline            TIMESTAMPTZ NOT NULL,
    allowed_capabilities JSONB DEFAULT '[]',
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    completed_at        TIMESTAMPTZ
);

-- 关键约束：同一 Session 最多一个 ACTIVE 操作
CREATE UNIQUE INDEX uq_active_operation_per_session
ON exclusive_operations(session_id)
WHERE state = 'ACTIVE';

-- 索引
CREATE INDEX idx_exclusive_operations_session_id ON exclusive_operations(session_id);
CREATE INDEX idx_exclusive_operations_state ON exclusive_operations(state);
CREATE INDEX idx_exclusive_operations_deadline ON exclusive_operations(deadline) WHERE state = 'ACTIVE';
```

### 3.5 durable_workflows — 持久化工作流表

```sql
CREATE TABLE durable_workflows (
    workflow_id         TEXT PRIMARY KEY,
    session_id          TEXT NOT NULL REFERENCES sessions(id),
    operation_id        TEXT NOT NULL REFERENCES exclusive_operations(operation_id),
    workflow_type       TEXT NOT NULL,
    attempt             INTEGER NOT NULL DEFAULT 1,
    priority            INTEGER NOT NULL DEFAULT 0,
    state               TEXT NOT NULL DEFAULT 'PENDING',
    phase               TEXT,
    worker_id           TEXT,
    coordinator_term    BIGINT NOT NULL,
    context_epoch       BIGINT NOT NULL,
    operation_epoch     BIGINT NOT NULL,
    dispatched_at       TIMESTAMPTZ,
    started_at          TIMESTAMPTZ,
    heartbeat_at        TIMESTAMPTZ,
    phase_deadline      TIMESTAMPTZ,
    operation_deadline  TIMESTAMPTZ,
    cancellation_epoch  BIGINT NOT NULL DEFAULT 0,
    idempotency_key     TEXT,
    external_receipt    TEXT,
    failure_reason      TEXT,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    completed_at        TIMESTAMPTZ
);

-- 索引
CREATE INDEX idx_durable_workflows_session_id ON durable_workflows(session_id);
CREATE INDEX idx_durable_workflows_operation_id ON durable_workflows(operation_id);
CREATE INDEX idx_durable_workflows_state ON durable_workflows(state);
CREATE INDEX idx_durable_workflows_phase_deadline ON durable_workflows(phase_deadline) WHERE state = 'RUNNING';
CREATE INDEX idx_durable_workflows_heartbeat ON durable_workflows(heartbeat_at) WHERE state = 'RUNNING';
```

**工作流状态机**：

```
Pending → Dispatched → Running → Completing → Completed
                ↓           ↓          ↓
            Cancelled    Failed    TimedOut
                            ↓          ↓
                        DeadLetter  Compensating → Compensated → DeadLetter
```

### 3.6 outbox_events — 事件发布表

```sql
CREATE TABLE outbox_events (
    event_id            TEXT PRIMARY KEY,
    aggregate_type      TEXT NOT NULL,
    aggregate_id        TEXT NOT NULL,
    event_type          TEXT NOT NULL,
    schema_version      INTEGER NOT NULL DEFAULT 1,
    payload             JSONB NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    published_at        TIMESTAMPTZ,
    publish_attempts    INTEGER NOT NULL DEFAULT 0,
    next_attempt_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_error          TEXT,
    dead_lettered_at    TIMESTAMPTZ,
    route_epoch         BIGINT,
    coordinator_shard_id INTEGER,
    dispatch_owner      TEXT,
    dispatch_lease_until TIMESTAMPTZ
);

-- 未发布事件查询
CREATE INDEX idx_outbox_events_unpublished
ON outbox_events(next_attempt_at, created_at)
WHERE published_at IS NULL AND dead_lettered_at IS NULL;

-- 按聚合查询
CREATE INDEX idx_outbox_events_aggregate ON outbox_events(aggregate_type, aggregate_id);
```

V041 为 Node Command Outbox 增加可空 Route/Claim 字段。新 Writer 在同一业务事务中捕获
权威 Route Epoch/Shard；动态派发 Worker 使用短 Lease 和 `FOR UPDATE SKIP LOCKED`
领取行。N-1 Writer 保持四列为空并由兼容路径排空。用于大表派发的部分索引通过
`database/online-migrations/create_outbox_node_command_shard_claim_index.sql`
在线创建，不放入启动 Flyway 事务。

### 3.6.1 coordinator_dispatch_workers — 物理派发 Worker 租约

```sql
CREATE TABLE coordinator_dispatch_workers (
```

## 4. Redis 数据结构

### 4.1 Session 路由缓存

```
Key: session:route:{session_id}
Type: Hash
Fields:
  - node_id: "node-001"
  - coordinator_shard: "shard-03"
  - coordinator_owner: "coord-pod-01"
  - updated_at: "2026-07-23T10:00:00Z"
TTL: 5 minutes
```

### 4.2 Coordinator 心跳

```
Key: coordinator:heartbeat:{session_id}
Type: String
Value: ISO timestamp
TTL: 30 seconds
```

### 4.3 当前状态视图（短期缓存）

```
Key: state:current:{session_id}
Type: Hash
Fields:
  - state_version: "42"
  - state_hash: "abc123..."
  - state_quality: "COMPLETE"
  - url: "https://example.com"
  - title: "Example Page"
TTL: 1 minute
```

### 4.4 操作锁（加速）

```
Key: operation:active:{session_id}
Type: String
Value: operation_id
TTL: 根据 operation deadline
```

### 4.5 幂等键缓存

```
Key: idempotency:{key}
Type: String
Value: JSON response
TTL: 24 hours
```

## 5. 迁移策略

### 5.1 迁移工具

使用 Flyway 管理 PostgreSQL 迁移。

### 5.2 迁移文件命名

```
V{version}__{description}.sql
```

示例：
- `V001__initial_control_plane.sql`
- `V002__add_workflow_tables.sql`
- `V003__add_audit_events.sql`

### 5.3 迁移安全检查

每次迁移需要：

| 检查项 | 说明 |
|--------|------|
| migration_owner | 迁移负责人 |
| backward_compatibility_test | 向后兼容测试 |
| rollback_or_forward_fix | 回滚或前向修复方案 |
| data_volume_estimate | 数据量估算 |
| lock_risk | 锁风险评估 |
| replication_lag_budget | 复制延迟预算 |
| canary_tenant | 金丝雀租户 |
| completion_receipt | 完成确认 |

### 5.4 Expand/Migrate/Contract 模式

```
1. Expand: 新增字段（Nullable 或 Default）
2. Deploy Compatible Readers: 部署可读新字段的服务
3. Deploy Compatible Writers: 部署写入新字段的服务
4. Backfill / Migrate: 回填历史数据
5. Observe: 观察系统稳定
6. Contract: 移除旧字段（可选）
```

## 6. 索引策略

### 6.1 索引原则

- 只为高频查询创建索引
- 避免过度索引影响写性能
- 使用部分索引减少索引大小
- 定期分析索引使用情况

### 6.2 关键索引

| 表 | 索引 | 用途 |
|------|------|------|
| sessions | (tenant_id, state) | 租户 Session 列表 |
| session_contexts | (session_id, context_epoch) | Context 查询 |
| exclusive_operations | (session_id) WHERE state='ACTIVE' | 活跃操作唯一约束 |
| durable_workflows | (state, phase_deadline) WHERE state='RUNNING' | 超时扫描 |
| outbox_events | (next_attempt_at, created_at) WHERE unpublished 且非 Dead Letter | 待重试事件 |
| audit_events | (tenant_id, created_at) | 审计查询 |

## 7. 数据保留策略

### 7.1 保留周期

| 数据类型 | 热存储 | 温存储 | 冷存储 | 删除 |
|---------|--------|--------|--------|------|
| Session 主数据 | 30 天 | 90 天 | 1 年 | 手动 |
| Context 历史 | 7 天 | 30 天 | 90 天 | 自动 |
| Operation 记录 | 7 天 | 30 天 | 90 天 | 自动 |
| Workflow 记录 | 3 天 | 14 天 | 30 天 | 自动 |
| Outbox Events | 发布后删除 | - | - | 自动 |
| Audit Events | 90 天 | 1 年 | 7 年 | 合规 |
| Profile 数据 | 按租户策略 | 按租户策略 | 按租户策略 | 租户控制 |

### 7.2 清理任务

```sql
-- 清理已发布 Outbox Events
DELETE FROM outbox_events WHERE published_at < now() - interval '1 day';

-- 清理已完成 Workflows
DELETE FROM durable_workflows
WHERE state IN ('COMPLETED', 'CANCELLED', 'COMPENSATED')
AND completed_at < now() - interval '30 days';

-- 清理旧 Context 历史
DELETE FROM session_contexts
WHERE committed_at < now() - interval '90 days';
```
