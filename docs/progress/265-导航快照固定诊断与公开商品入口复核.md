`NAVIGATION_STATE_UNAVAILABLE`。测试抽取实际 `create_execute_task`，验证精确错误码可见，

**32 项通过**。

Node 的导航后快照失败只记录 Node 创建的类型化类别：主 Frame/Loader 前后不一致为
`DOCUMENT_CHANGED`，主文档身份缺失或不是根 Frame 为 `DOCUMENT_IDENTITY_UNAVAILABLE`。
其他错误固定 `UNKNOWN`，不依据页面文本或自由错误字符串猜测类别。原错误显示文本、
公共失败码、拒绝行为与截止时间保持不变；没有自动重试敏感输入。
真实 WebSocket 回归验证类型和原拒绝文本，另验证私有错误正文不会进入类别。

## 不同运行分别判定

全部使用隔离 Session、网站公开测试账号和一次性 Secret API，没有进入 Checkout。
实际 Gate 的断言和截止时间没有放宽；以下失败不合并归因：

1. `run49tvf`：登录、Inventory 通过，商品详情 NAVIGATE 失败；旧白名单未保留精确码，
   不据新诊断追溯认定该轮原因。
2. `pcqzez99`：登录、Inventory 通过，商品详情返回 `NAVIGATION_STATE_UNAVAILABLE`；
   该轮没有类型化快照原因。
3. `pdsksffb`：登录入口等待失败。独立 CDP 同时看到实际应用 root 没有子元素，
   Document complete、全页 STABLE、Target 为零；原因未确定，不能认定是投影遗漏。
4. `tzsti0xg`：登录、Inventory 通过；详情直接导航得到实际 Document HTTP 404，随后
   脚本发起新 Document，Node 前后根 Loader 不同并记录 `DOCUMENT_CHANGED`。
   这是该轮的受信快照拒绝证据，不是所有历史导航失败的统一解释。
5. `qqsufkha`：尚未到达商品入口，敏感 `TYPE_TEXT` 返回 `STATE_STALE`。
   Node 原拒绝是 `target revision is stale`；API 快照当时 FRESH、年龄约 0.44—1.46 秒，
   不能归因为新鲜度超龄，也不能因此忽略 Target Revision。
6. `i8zjhspx`：登录后到达商品入口定位，入口角色/可操作性断言失败，尚未点击。
   页面入口点击方案仍待实际验证，不计为 Commerce 通过。
7. `mcbmzgqz`：登录后两个同名商品入口均是可见 button，但 `interactive=false`。
   当前实体歧义策略拒绝这种缺业务键的目标；没有选择任意一个强行点击。
   未验证的页面入口点击改动未提交，后续复核执行路径是否也一致拒绝该标记。

日志目录均为 `/tmp/ab-login-probe.<上述标识>/`，只导出有限枚举、计数和身份摘要；
不在文档或常规输出中复制测试 Secret、页面正文、完整 URL 或供应商请求。
