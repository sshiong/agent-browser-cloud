# 原生属性观察可信引用与接收者副作用实验

> 日期：2026-10-07
> 基线：8f774242826c79f5d67cf2bf5bc73986a7e226ac
> 范围：自有 Chrome 的候选机制验证；未接入生产 State Collector。

## 可信引用的候选捕获

progress 278 的实验通过页面 Object.getOwnPropertyDescriptor 取得原生 checked setter。
页面能替换该 helper、HTMLInputElement 全局属性或 prototype accessor，不能直接把
页面提供的引用当作生产可信函数。

本次实验先用 Runtime.evaluate 的 throwOnSideEffect 读取接口构造器，再用 CDP
Runtime.getProperties 检查自己的 prototype 和 checked setter。构造器必须符合精确
原生元数据，prototype 必须不可写/不可配置；JS 位置、Bound/Proxy 内部属性和非原生
setter 均拒绝。不调用页面 descriptor helper，不依赖页面 Function.toString。

真实 Chrome 测试已验证：替换 descriptor helper 后仍能捕获且调用数为零；有副作用
的全局 getter 被拒绝且执行次数为零；JS、Bound、Proxy 构造器和 JS setter 都被拒绝。
恢复真实接口后可重新捕获。这个实验只覆盖 checked 的引用，未证明其他全部 Intrinsic。

## 接收者属性读取不适合作为生产观察条件

旧候选的 `(this[key]?.(), false)` 会先读取接收者属性。真实 Chrome 的原生 setter
断点条件在原生接收者检查之前就执行；三个独立自有用例结果如下：

| 接收者 | 真实动作结果 | 页面 getter/trap 次数 | 已登记元素计数增量 | 暂停 |
| --- | --- | --- | --- | --- |
| 普通对象 | 原生 setter 拒绝接收者 | 1 | 0 | 0 |
| 包装真实 input 的 Proxy | 原生 setter 拒绝接收者 | 1 | 0 | 0 |
| 未登记的离线 checkbox | checked 实际改变并恢复 | 2 | 0 | 0 |

因此不可替换的已登记元素回调仍不能防止在未知接收者上执行页面代码，旧候选不能
直接接入生产；旧实验只证明自有已登记元素上的行为，没有形成生产承诺。

## 单 Realm 回调的缺口与替代实验

将条件换成主 Realm 私有 lexical 回调可去掉接收者属性读取，但只在主 Realm 登记
会漏掉外 Realm 原生 setter。自有同源 iframe 的实际改变/恢复仍成立，主计数增量为零。
通过 RemoteObject 参数向不同默认 Frame Context 传递回调的独立实验也被 CDP 拒绝，
不能假定一个回调天然覆盖所有 Realm。

替代实验在两个自有同源默认 Realm 分别建立闭包 WeakMap，登记同一个根文档元素；
条件只将接收者作为 WeakMap 原生查询键，不读取接收者属性。固定 false 条件保持不暂停。

| setter 来源 | 调用方 | 主 Realm 增量 | 子 Realm 增量 | 暂停 |
| --- | --- | --- | --- | --- |
| 主 Realm | 主 Realm | 2 | 0 | 0 |
| 子 Realm | 主 Realm | 0 | 2 | 0 |
| 主 Realm | 子 Realm | 2 | 0 | 0 |
| 子 Realm | 子 Realm | 0 | 2 | 0 |

上述未知对象、Proxy、未登记 checkbox 三类用例再次执行：真实拒绝或改变/恢复保留，
页面 getter/trap 次数均为零，两个登记计数均不变，未出现 Debugger.paused。
这些负例和四种调用组合已进入同一仓库真实 Chrome 测试；任何暂停都立即失败，绝不
因为断点 ID 相同就发送 resume。原双客户端条件共存/精准移除与元素隔离断言保留。
