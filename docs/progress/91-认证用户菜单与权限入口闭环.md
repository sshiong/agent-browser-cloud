# 认证用户菜单与权限入口闭环

> 日期：2026-07-31
> 适用端：Web Console 与 Tauri 2 共享 React UI
> 数据来源：现有 OIDC / 本地开发认证上下文

## 本轮结论

顶部静态身份块和独立退出图标已替换为完整用户菜单。菜单只展示当前认证上下文中的
Tenant、Actor 和角色，不创建账户 Mock、不使用 `localStorage`，也不提供尚未实现的
个人资料或会话管理死链接。

Web 与未来 Tauri 桌面端继续复用同一组件、认证 Provider、权限判断与路由。生产 OIDC
模式调用现有 `signoutRedirect`；本地开发模式明确标识身份来源且不伪造退出行为。

## 已完成

- 顶部用户入口在桌面显示 Actor/Tenant，在窄屏保留 40px 可触控头像按钮；
- 菜单展示真实 Tenant、Actor、认证模式和当前角色；
- 平台角色转换为可读中文，同时保留原始角色代码作为辅助说明；
- Workspace 设置只对 `TENANT_ADMIN / SECURITY_ADMIN / PLATFORM_ADMIN` 展示；
- 安全中心只对 `SECURITY_ADMIN / PLATFORM_ADMIN` 展示；
- OIDC 模式提供真实退出动作，阻止重复提交，并在跳转失败时保留菜单和显示错误；
- Local 模式显示“本地开发身份、生产环境不启用”，不提供无效退出按钮；
- 菜单支持鼠标、触控、Enter、Escape、方向键和焦点环；
- 使用 Radix Portal 与碰撞边界，390×844 视口不会被固定侧栏或浏览器边缘裁切；
- 未增加账户 Profile、密码、会话管理等尚无正式后端契约的入口。

## 权限边界

```text
认证身份
  ├─ Tenant / Actor / Roles：只读展示
  ├─ Tenant Admin+：Workspace 设置
  ├─ Security Admin+：安全中心
  └─ OIDC：身份提供商退出重定向
```

菜单隐藏入口只用于减少误操作；服务端 RBAC 仍是最终授权边界。用户菜单不会绕过既有
路由权限 Gate，也不会在前端推导或提升角色。

## 验收证据

- Java/Rust/Web 全仓 Lint 与单元测试通过；Web 为 18 个文件、60 项测试；
- OpenAPI/Proto/JSON Schema Contract Check 与 V065 N/N−1 Upgrade Gate 通过；
- Tauri Rust Lint、2 项测试、共享 Web Production Build 和 macOS 本机无安装包构建通过；
- 完整 PostgreSQL/双 Control Plane/三 Browser Node/MinIO/mTLS Integration 通过，
  输出 `workspace_notification_center=true`、`workspace_theme_preferences=true`，
  且既有 Session/Operation/迁移/审计主链无回归；
- 1440px 桌面视口确认身份、角色、设置和安全入口完整可见；
- 390×844 视口确认顶部按钮与 300px 菜单均不溢出；
- Escape 关闭后焦点回到触发器，Enter 重新打开，ArrowDown 可逐项移动；
- 本地模式确认没有虚假退出动作；
- 正式 OIDC 退出沿用 Web/Tauri 共用 `AuthProvider.logout()`。
