## 可重复代码缺口

原观察器仅保存当前 Frame/Loader → 主 Document 关系。主文档前进后，迟到事件如果
引用此前已提交的旧 Loader，就失去精确归属；迟到的子 Frame Document 则可能按
当前父树继承新主文档。前者阻塞当前页静默，后者把旧文档请求误归给新父文档。

实际旧生产代码的两项状态机回归失败。另通过真实 TCP/WebSocket 注入“先提交新主
文档，再收到旧 POST/XHR 与 POST/Document”事件顺序：旧观察器无法形成当前 Tab
quiet，该回归也失败；编译成功，失败来自运行断言。

progress 272 的公开 OTP 全量失败没有证明这种迟到事件顺序，故该次失败根因继续
保留。那轮只读 CDP 的最后未完成旧 Loader 请求不等于同一时刻 Node 的计数或静默
投影错误；最后 API 的时间差和当前 Loader 的周期请求仍需一起核验。

## 有界证明与保护

- 最多 512 份已提交上下文证明，键为精确 CDP Session/Frame/Loader，值为此前验证
  的主 Frame/Loader；child commit 仍要求当前已验证的父树。FIFO 淘汰，记录不含 URL
  或业务正文，不公开到 API。
- 有效主文档前进保留历史证明，迟到请求先查精确历史，再走现有当前 Frame 规则。
  同一 Frame/Loader 在不同主 Document 下出现时，该 CDP Session 持续停用文档过滤，
  直到 Session 脱离后重建；容量淘汰和普通 context clear 不会忘记已观察到的冲突。
  无冲突的历史主 Loader 恢复时，未完成请求重新计入当前 Tab。
- 无效上下文、根 Frame 脱离、CDP Session 移除会清除该 Session 的历史证明；子 Frame
  移除/未知原因或未知父链会清除该 Frame 证明，既有 renderer swap 规则保留。observer
  重连使用新 Tracker，旧证明不会跨观察连接延续。
- 证明未知、淘汰或冲突的请求继续阻塞当前页。精确旧文档归属只影响当前 Tab 统计；
  全局请求、Upload、Form、SPA 写入、Payment/Security 与 Critical Transaction 仍保留。
  只有既有真实生命周期/网络结束事件收尾，原事务 settle window 继续执行。
