# 远程桌面有效帧龄展示与补丁上下文修复

> 日期：2026-09-28
> 范围：Gateway 连接私有帧龄、Web/Tauri 共用 noVNC 绘制提示、可重现 pnpm 补丁。

Gateway 在每个已对齐 Viewer 的 20 字节 `ABCF` Fence 中附加图像来源到发送时的单调帧龄。旧 Viewer 继续收到 16 字节 Fence；8 字节旧私有 Fence 仍可由 noVNC 兼容回执。Gateway 在收到精确回执及基于该帧的输入时，以自身单调时钟记录连接私有 `effective_frame_age_ms`，断开后清除。帧身份仍由前 16 字节验证，客户端时钟不参与输入围栏。

noVNC 在 Canvas 绘制队列清空后的下一动画帧，将 Fence 附带的来源帧龄加上本地接收至绘制耗时，并发出 `agentbrowserframe` 事件。Web/Tauri 共用 Viewport 显示最近一帧的“来源→绘制”估计。这个客户端值不含 Fence 发送至客户端的网络耗时，是绘制时帧龄的**下界估计**；Gateway 的回执后指标包含该传输耗时，但也包括回程。因此不把它称为物理显示器呈现时间或精确用户可见帧龄。

原有零上下文 noVNC 补丁在重装时存在错误插入位置的风险。新补丁保留源码上下文，且 `.gitattributes` 对统一 diff 上下文中的空行忽略尾空格检查。已将补丁应用到未修改包并逐字节对比目标源码，再经过 frozen lockfile 安装、源码语法检查、5 项协议测试、Web 145 项、Lint 和生产构建。

Gateway 36 项测试与严格 Clippy 通过，包括真实 WebSocket/RFB 的 20 字节回执、过期点击拒绝、上游释放和连接帧龄清理。`018a7e1` 的 CI 与 Desktop 工作流均通过，包含完整 Integration；本次提交的 `ci` run `36403273895` 与 `desktop` run `36403273772` 也均通过。随后完整 Web/noVNC E2E 找到连续帧输入问题并由 [进度 235](235-远程桌面连续帧输入与真实Web回归.md)修复。旧 Viewer 无输入围栏、客户端帧龄下界估计、物理显示、目标 Linux 八客户端小时级长稳与硬件 Codec 仍是独立边界。
