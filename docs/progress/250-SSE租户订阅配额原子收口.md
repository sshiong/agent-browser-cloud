## 复现

进度 249 已修复通道注册与 Replay 游标竞态。继续审查发现租户配额存在独立问题：
注册先从 Map 取出 AtomicInteger，随后在 Map 外增加计数；最后一个旧连接退出时
可把该对象减到零并移出 Map。注册连接继续增加已经脱离 Map 的对象，下一次注册
新建另一对象，从而突破租户上限。实例全局计数不能替代租户计数。

四项确定性回归均在旧代码失败：配置实例上限 10、租户上限 1，在替换连接取得
计数对象后触发旧连接真实的 Spring Emitter completion callback；替换连接仍活跃
时额外订阅未被拒绝。用有界 Latch 控制交错，没有随机睡眠或重复碰撞试验。

测试仅通过 Reflection 注入隔离的传输计数 Map、触发 Framework 已注册 callback，
不直接调用业务服务的私有配额增减方法，不伪造生产业务状态或 PostgreSQL 数据。

## 修改

- 租户计数查找、检查和增加均在 `ConcurrentHashMap.compute` 的同一键原子操作中。
- 退出通过 `computeIfPresent` 减少计数，并在同一操作中回收零计数对象。
- 租户拒绝时退还原实例全局预约；重复 completion 仍由已有 Subscriber 活跃围栏处理。
- 保留原配置上限、Tenant 隔离、HTTP 错误、事件源与 SSE 协议；不添加容量豁免。
- Session/Resource 的同 Session 订阅限制保持原机制；本次不改变集群级容量定义。
- API、数据库、SDK、OpenAPI、Protobuf 无变更。
