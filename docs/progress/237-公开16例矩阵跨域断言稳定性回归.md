# 公开 16 例矩阵跨域断言稳定性回归

> 日期：2026-09-29
> 范围：单 Session、真实 Chrome、公开 URL Agent Replay。

## 发现与修正

进度 236 后的完整矩阵一次连续执行已通过公开表单、练习登录、固定码 OTP、React
TodoMVC、Sauce Labs 购物车、Duende 演示站内登录、普通与跨域托管 Challenge，
但最后的 `cross-domain-fail-closed` 用例拿到刚导航后的 Target 后立即提交点击。
Target Revision 在执行前变化，Node 正确以 `STATE_STALE` 拒绝；用例要求的
`POST_ACTION_DOMAIN_NOT_ALLOWED` 因而没有被实际检验。

Replay 现在等到 `https://example.com/` 的权威 State 同时为可执行、`FRESH`、
`STABLE` 且存在可见可用链接，再提交点击。断言仍要求精确的跨域拒绝码，
没有把 `STATE_STALE` 当作跨域策略通过。失败输出只保留 Task 最小诊断，
避免完整 Plan 和 Target 列表进入矩阵日志。产品侧动作围栏未改动。

  `git diff --check` 通过。

本轮取得的是**一次完整通过**。紧接着的第二轮在公开 OTP 入口等待 `STABLE` 时超时：
State 保持 `FRESH`，DOM/Layout 已安静，但 `networkQuietMillis=0`、页面持续 `CHANGING`。
该轮没有越过稳定性门禁，尚不能从现有输出判断是网络观察缺口还是仍有在途请求；
Replay 的最小诊断现补充 `networkEvidenceFresh` 和 `documentReadyState`，供下轮区分。
此前公开页面加载、CDP 采样和页面稳定性也曾使不同轮次失败；连续长稳仍需重复全量通过
及目标 Linux 证据。公开练习站的固定码不证明真实短信、邮件或
TOTP 交付；Duende 站内登录不证明独立 OIDC Client/企业 IdP；购物车不证明支付。
