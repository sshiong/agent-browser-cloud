# 环境布局、详情空值与远程桌面流畅模式

> 日期：2026-09-03
> 状态：代码、本地 Gate 与 OrbStack 真实画面验收通过；本轮 GitHub 待提交检查。

## 根因与修复

- 环境列表启动成功提示长期占据操作列，Context 也会被挤压换行。共享启停组件使用固定
  按钮占位，成功消息以无布局占位的 accessible status 播报；错误详情绝对定位，Context
  分两行且不拆词，表格窄屏横向滚动，详情按钮不压缩。Web/Tauri 共用。
- 首个环境详情实测白屏，控制台为 `maximumHourlyCost=null` 调用 `toFixed`。
  对 null/undefined 均显示未知而非生成价格；类型与 SSR 回归覆盖实际空值。
- Gateway 原来只向 noVNC 发 Raw，前端 qualityLevel 并不影响传输。保留单上游与精确
  Raw 基线，在每连接按标准 SetEncodings 的 Tight(7)/Quality(-32…-23) 协商编码：
  流畅档 quality2 → JPEG30/4:2:0；均衡档 quality6 → JPEG70/4:4:4；清晰档 quality9
  → 原始像素。旧 Raw-only 客户端保持兼容。
- 首帧等待客户端请求后按实际编码字节计入既有 Actor/Session 配额。JPEG 独立矩形无
  跨 Viewer 压缩状态，晚加入基线不依赖其他连接；切换画质重发当前完整基线，静止页面也
  能从有损恢复清晰。小矩形/压缩更大时回退 Raw。编码在有界连接的 blocking task 中执行。
- UI 默认流畅，支持在线切换，不重签票据或改变只读/协作权限。仅真实输入优先 Agent，
  既有隔离、撤销、慢消费者、带宽及 FPS 上限保留。画面标注配额上限不是实测 FPS。

## 明确边界

本模式降低传输画质和色彩采样，不降低 Chromium 页面分辨率，也不承诺60 FPS。
默认只读 Actor 上限15、协作控制上限30，且仍受 Workspace/资源策略限制。真正低分辨率
独立视图、硬件编码、8协作者弱网/长稳及动态实测 FPS 矩阵尚未完成，不能写为已验收。
