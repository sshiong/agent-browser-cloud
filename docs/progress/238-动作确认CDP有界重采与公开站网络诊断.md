# 动作确认 CDP 有界重采与公开站网络诊断

> 日期：2026-10-02
> 范围：Browser Node 动作确认采集、公开 URL Replay 失败诊断。

## 动作确认重采

公开练习站一次成功登录提交在点击后的页面采集中报告
`CDP Runtime.evaluate timed out`，使 Task 进入 `ACTION_TIMEOUT`。
输入可能已经生效，故重复点击不能作为通用修复。

State Collector 现在只在动作确认读取遇到 `Runtime.evaluate` 超时或等待结果期间
WebSocket 正常关闭时，延迟 100 毫秒并重新读取一次活动页面的真实 State。
两次均无法取得 State 时仍返回错误；其他读取错误直接失败。
普通周期采集不增加重试，输入派发不重放。确认结果仍经既有 Operation/Epoch、
状态和域名围栏校验，不能仅凭输入已发出判定业务成功。

## 公开站网络诊断

Replay 等待页面稳定时可能尚未派发动作，原动作超时诊断因而无法说明网络静默为何为零。
Node 增加 Debug 级在途请求数量与有界类别诊断，公开矩阵单独开启并在失败时保留最后
60 条。日志不增加请求 URL、Header、正文、验证码或凭据。

9 月 29 日带诊断的完整回放在练习站登录入口观察到一个持续在途的 `XHR:script`：
`documentReadyState=complete`、`networkEvidenceFresh=true`，但网络静默为零。
10 月 2 日回放则观察到两个持续在途的 `XHR:script`。平台未放行后续输入。
尝试的一次同页导航恢复也失败，已撤去该测试恢复逻辑；正式 Dataset、单 Session
范围和稳定性断言保持原样。现有类别日志尚不能证明 XHR 是真实未结束请求还是
缺失终态事件，须进一步取得协议事件证据，不能据此排除所有脚本请求。
