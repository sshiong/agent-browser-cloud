# VNC 有界多协作者与只读观察闭环

> 日期：2026-08-11
> 状态：代码、契约、三栈全量测试、真实托管双 Client E2E 和 SDK 生成完成；目标 Linux 长稳待执行。

## 问题

进度 115 已经关闭“打开 VNC 就停止 Agent”的错误语义，但数据面仍有三个限制：

- Gateway 使用 Session 级 `HashSet` 拒绝第二个 VNC Client；
- x11vnc 使用 `-nevershared`，noVNC 发送 `shared=false`；
- `viewOnly` 只是响应字段，没有由签名票据和 Browser Node 强制执行。

因此同一 Session 不能同时由操作者和观察者查看，而且只依靠浏览器端禁用输入不足以构成
生产安全边界。

## 已完成

### Browser Node 连接仲裁

- 每个 Session 保存按单次票据 Nonce 建立的连接 Lease，最多允许 8 个协作连接；超过上限
  在 WebSocket 握手阶段返回 `429`，避免观察连接线性放大 Node 编码和网络负载；
- 每条连接都有独立 Revocation Channel。显式 `EXCLUSIVE_TAKEOVER` 票据会先撤销全部
  Collaborative Lease，再成为唯一连接；接管存续期间新的协作票据返回 `409`；
- 连接断开只删除自己的 Nonce。还有其他协作者时不执行全局清键；最后一个连接断开并经过
  Grace/Generation 校验后，才执行 CDP `release_all`、X11 All-keys-up 和 State Resync；
- Session 注销会主动撤销全部连接，旧代理任务不能继续持有桌面数据面。

### 服务端只读模式

- `POST /api/v1/sessions/{id}:desktop-connection?viewOnly=true` 将 `viewOnly` 写入 HMAC
  签名 Claim 和正式响应，不接受客户端自行声明；
- noVNC 根据服务端响应启用 `client.viewOnly`；Browser Node 仍独立解析 RFB KeyEvent、
  PointerEvent 和 ClientCutText。只读连接尝试输入时会在写入 x11vnc 前关闭，不能绕过
  浏览器 UI；
- 显式 HumanTakeover 始终签发可控制的独占票据，不会被只读查询参数降级成语义不一致的
  “只读接管”。

### RFB 与共享 UI

- Runtime Supervisor 将 x11vnc 从 `-nevershared` 改为 `-shared -dontdisconnect`；
- noVNC 使用 `shared=true`，新观察页面不会要求 x11vnc 断开已有连接；
- Web/Tauri 共享远程桌面页提供“协作控制 / 只读观察”切换，切换时重新签发精确模式票据；
  状态区明确显示 `VIEW ONLY / SHARED`、`CONTROL / SHARED`、最多 8 个协作者以及 Node
  强制输入拒绝，不只依靠颜色表达；
- OpenAPI 和 TypeScript/Python/Go/Java SDK 已同步 `viewOnly` 查询参数。
