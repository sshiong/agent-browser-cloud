## 1. 代码规范

### 1.1 通用原则

| 原则 | 说明 |
|------|------|
| 模块边界清晰 | Domain 不依赖 Spring，不依赖具体框架 |
| 依赖方向明确 | api → application → domain，infrastructure → domain |
| 单一职责 | 每个类/函数只做一件事 |
| 显式优于隐式 | 参数、返回值、错误都要明确 |
| 不可变优先 | 优先使用 record、struct、const |
| 最小权限 | 只授予必要的访问权限 |

### 1.2 Java 规范

#### 代码风格

- 使用 Google Java Format
- 类名：PascalCase
- 方法名：camelCase
- 常量：UPPER_SNAKE_CASE
- 包名：全小写，点分隔

#### 命名规范

```java
// ✅ 正确
public record SessionContext(
    String sessionId,
    String tenantId,
    SessionState state
) {}

// ❌ 错误
public class session_context {
    public String session_id;
    public String tenant_id;
}
```

#### 领域对象

```java
// 使用 record 表示值对象
public record ExclusiveOperation(
    String operationId,
    String sessionId,
    OwnerType ownerType,
    OperationMode mode
) {}

// 使用 sealed interface 表示密封类型
public sealed interface SessionCommand permits
    StartSession,
    TerminateSession,
    NodeEventReceived {
    String sessionId();
}

// 使用 enum 表示状态
public enum SessionState {
    CREATED,
    STARTING,
    RUNNING,
    TERMINATED,
    FAILED
}
```

#### 异常处理

```java
// ✅ 使用领域异常
throw new ActiveOperationExistsException(sessionId);

// ❌ 使用通用异常
throw new RuntimeException("Operation already exists");

// ✅ 明确的错误码
public record ApiError(
    String code,
    String message,
    Map<String, Object> details
) {}
```

#### 依赖注入

```java
// ✅ 构造器注入
@RestController
public final class SessionController {
    private final SessionApplicationService service;

    public SessionController(SessionApplicationService service) {
        this.service = service;
    }
}

// ❌ 字段注入
@RestController
public class SessionController {
    @Autowired
    private SessionApplicationService service;
}
```

### 1.3 Rust 规范

#### 代码风格

- 使用 `rustfmt` 默认配置
- 使用 `clippy` 进行代码检查
- 结构体：PascalCase
- 函数/变量：snake_case
- 常量：SCREAMING_SNAKE_CASE
- 模块：snake_case

#### 命名规范

```rust
// ✅ 正确

    pub session_id: String,
    pub tenant_id: String,
    pub state: SessionState,
}

// ❌ 错误
```

#### 错误处理

```rust
// ✅ 使用 anyhow 进行应用错误处理
use anyhow::{Result, Context};

fn start_runtime(spec: &RuntimeSpec) -> Result<RuntimeHandle> {
    let child = Command::new(&spec.chromium_binary)
        .spawn()
        .context("Failed to start Chromium")?;

    Ok(RuntimeHandle { ... })
}

// ✅ 使用 thiserror 进行库错误定义
use thiserror::Error;

#[derive(Error, Debug)]
pub enum NodeError {
    #[error("Runtime not found: {session_id}")]
    RuntimeNotFound { session_id: String },

    #[error("Stale coordinator term: expected {expected}, got {actual}")]
    StaleTerm { expected: u64, actual: u64 },
}
```

#### 异步编程

```rust
// ✅ 使用 async/trait
use async_trait::async_trait;

#[async_trait]
pub trait RuntimeSupervisor: Send + Sync {
    async fn start(&self, spec: RuntimeSpec) -> Result<RuntimeHandle>;
    async fn stop(&self, session_id: &str) -> Result<()>;

// ✅ 使用 tokio
#[tokio::main]
async fn main() -> Result<()> {
    let supervisor = ChromiumRuntimeSupervisor::new();
    supervisor.start(spec).await?;
    Ok(())
}
```

#### 测试


### 1.4 TypeScript 规范

#### 代码风格

- 使用 ESLint + Prettier
- 组件：PascalCase
- 函数/变量：camelCase
- 常量：UPPER_SNAKE_CASE
- 文件：kebab-case.ts 或 PascalCase.tsx（组件）

#### 类型定义

```typescript
// ✅ 使用 interface 定义数据结构
interface SessionContext {

// ✅ 使用 type 定义联合类型
type SessionState =
  | 'CREATED'
  | 'STARTING'

  | 'TERMINATED'
  | 'FAILED';

// ✅ 使用 enum 定义枚举（当需要运行时值时）

  L1 = 'L1',
  L2 = 'L2',
  L3 = 'L3',

```

#### 组件规范

```tsx
// ✅ 函数组件 + TypeScript
interface SessionCardProps {
  session: SessionView;
  onSelect: (sessionId: string) => void;
}

export function SessionCard({ session, onSelect }: SessionCardProps) {
  return (
    <div onClick={() => onSelect(session.sessionId)}>
      <h3>{session.sessionId}</h3>
      <span>{session.state}</span>
    </div>
  );
}

// ✅ 自定义 Hook
function useSession(sessionId: string) {
  const [session, setSession] = useState<SessionView | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    getSession(sessionId).then(setSession).finally(() => setLoading(false));
  }, [sessionId]);

  return { session, loading };
}
```

#### API 调用

```typescript
// ✅ 类型安全的 API 调用
async function getSession(sessionId: string): Promise<SessionView> {
  const response = await fetch(`/api/v1/sessions/${sessionId}`);

  if (!response.ok) {
    throw new ApiError(response.status, await response.json());
  }

  return response.json();
}

// ✅ 错误处理
class ApiError extends Error {
  constructor(
    public status: number,
    public body: { code: string; message: string }
  ) {
    super(body.message);
  }
}
```

## 2. Git 规范

### 2.1 分支策略

```
main (生产)
  ↑
  ├── feature/xxx (功能分支)
  ├── fix/xxx (修复分支)
  └── refactor/xxx (重构分支)
```

- `main`：始终可发布
- 短生命周期 Feature Branch
- 不使用长期 `develop` 分支

### 2.2 Commit 规范

使用 Conventional Commits：

```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

**Type 类型**：

| Type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 |
| docs | 文档 |
| style | 格式（不影响代码运行） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试 |
| build | 构建系统 |
| ci | CI 配置 |
| chore | 其他 |

**示例**：

```
feat(session): add create session API

Implement POST /api/v1/sessions endpoint with:
- Idempotency-Key header support
- Input validation
- Error handling

Closes #123
```

**审查要点**：

| 维度 | 检查项 |
|------|--------|

## 3. 数据库规范

### 3.1 表命名

- 使用 snake_case
- 使用复数形式：`sessions`, `operations`
- 关联表使用下划线连接：`session_contexts`

### 3.2 字段命名

- 主键：`id` 或 `{table}_id`
- 外键：`{referenced_table}_id`
- 时间戳：`{action}_at`（如 `created_at`, `updated_at`）
- 布尔值：`is_{state}`（如 `is_active`, `is_deleted`）

### 3.3 索引命名

```
idx_{table}_{column(s)}
uq_{table}_{column(s)}
pk_{table}
fk_{table}_{referenced_table}
```

### 3.4 迁移规范

```sql
-- V001__initial_control_plane.sql
-- 描述：初始化控制面数据库

-- 创建表
CREATE TABLE sessions (
    id              TEXT PRIMARY KEY,
    tenant_id       TEXT NOT NULL,
    state           TEXT NOT NULL DEFAULT 'CREATED',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 创建索引
CREATE INDEX idx_sessions_tenant_id ON sessions(tenant_id);

-- 添加注释
COMMENT ON TABLE sessions IS 'Session 主表';
COMMENT ON COLUMN sessions.id IS 'Session ID';
```

## 4. API 规范

### 4.1 RESTful 规范

| 规则 | 说明 |
|------|------|
| URL 使用名词 | `/api/v1/sessions` 而非 `/api/v1/createSession` |
| 复数形式 | `/api/v1/sessions` 而非 `/api/v1/session` |
| HTTP 方法 | GET 读取，POST 创建/操作，PUT 替换，PATCH 部分更新，DELETE 删除 |
| 状态码 | 200 成功，201 创建成功，202 已接受，400 请求错误，404 未找到，409 冲突，500 服务器错误 |

### 4.2 命名规范

```
# URL: kebab-case
/api/v1/sessions/{session-id}

# Query 参数: camelCase
?pageSize=20&offset=0

# JSON Body: camelCase
{
  "sessionId": "ses_123",
  "tenantId": "tenant-1"
}
```

### 4.3 错误响应

```json
{
  "code": "SESSION_NOT_FOUND",
  "message": "Session not found: ses_123",
  "details": {
    "sessionId": "ses_123"
  },
  "requestId": "req_abc123",
  "timestamp": "2026-07-23T10:00:00Z"
}
```

### 4.4 幂等性

- 写操作支持 `Idempotency-Key` Header
- 幂等键有效期 24 小时
- 相同幂等键返回相同结果

## 6. 文档规范

### 6.1 代码注释

```java
/**
 * Session Coordinator 负责串行处理 Session 的状态转换。
 *
 * <p>每个 Session 有且只有一个 Active Exclusive Operation。
 * Coordinator 通过 PostgreSQL CAS 保证不会出现双主。
 *
 * @see SessionContext
 * @see ExclusiveOperation
 */
public final class SessionCoordinator {
    /**
     * 处理 Session 命令。
     *
     * @param command 要处理的命令
     * @return 处理结果
     * @throws ActiveOperationExistsException 如果已有活跃操作
     */
    public CoordinatorResult handle(SessionCommand command) {
        // ...
    }
}
```

### 6.2 README 规范

每个模块必须有 README.md，包含：

- 模块简介
- 构建/运行命令
- 配置说明
- API 文档链接

### 6.3 ADR 规范

```markdown
# ADR-001: 采用 Session Coordinator

## 状态
Accepted

## 背景
需要一个机制来保证同一 Session 不会有并发写操作。

## 决策
采用 Session Coordinator 模式，每个 Session 有且只有一个逻辑 Coordinator。

## 后果
- 优点：状态转换清晰，易于理解和调试
- 缺点：单点瓶颈，需要 Shard 支持规模化
```

### 7.1 测试命名

```java

@Test

// ❌ 错误
@Test
void test1() { ... }

@Test

```

### 7.2 测试结构

```java
@Test
void shouldRejectSecondActiveOperation() {
    // Given - 准备测试数据
    operationRepository.insert(activeOperation("session-1"));

    // When - 执行被测试操作
    var result = assertThrows(
        ActiveOperationExistsException.class,
        () -> coordinator.handle(new StartSession("session-1", ...))
    );

    // Then - 验证结果
    assertThat(result.getSessionId()).isEqualTo("session-1");
}
```
