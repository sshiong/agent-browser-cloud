## 本轮复现证据

progress 271 的加购目标身份丢失后，隔离真实 Chrome 商品定向再次失败，Gate exit 1。
独立只读 CDP 记录同一主 Frame/Loader 的 `historyApi` 事件：LOGIN → INVENTORY →
DETAIL，没有观察到返回库存路由。API 却在 DETAIL URL 下短暂投影 30 个库存目标，
含 Adapter 标记的库存商品标题与多枚 Add to cart；最后活动为 CHANGING。原回放仅按
名称找 Add to cart，因详情 URL 已相符，把旧库存按钮用作下一动作，Node 随后拒绝
不再存在的完整目标身份。

本轮证明了 SPA 可先更新路由、后替换内容这一就绪窗口；不能把 URL 相等或上一步
CLICK_TARGET verified 当作详情页面内容已就绪。它不是 HTTP 404、重复导航或许可放宽
的理由；没有把这份新观察追溯为 progress 271 那轮所有日志的唯一根因。
