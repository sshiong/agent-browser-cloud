## 缺口与实现

progress 267 的身份字段在控制面严格 Revision 校验之后才捕获，不能覆盖计划创建到
控制面授权之间的版本变化。现为计划在创建时捕获完整 Node Element ID，保存到已有
StepInput targetRef，拖拽同时捕获终点；保留原 Target Revision。只从同 Tenant、精确
请求 Revision、唯一、可交互的主文档目标读取合法完整 ID；缺失或子 Frame 保留旧引用。
捕获在一次性 Secret 消费之前，不从 DOM 位置、短 Target Ref 摘要或几何补造身份。

授权阶段只允许严格向前的 Revision，以及计划中已保存、仍在当前主文档唯一匹配的
完整实体 ID。当前数据库 Task 风险、Plan Step 风险、签名 Capability 风险必须共同
允许 progress 267 的重绑定范围，且 Node 声明精确能力。普通 R0/R1 与既有
AUTONOMOUS Credential/OTP 的 R2 例外可用；其他 R2、账号/财务/安全决定、旧 Node、
未知风险、旧短引用、未来/零 Revision、丢失身份、重复/不可交互目标与子 Frame仍拒绝。

Capability 校验和单次消费、Domain、Sensitive Input、角色、键值、动作预算与幂等流程
保留。失败在 Capability Use/Attempt/Outbox 前结束。提交给 Node 的 Plan Step 和原
Revision 不被改写；派发只附当前 State Version/Hash 与已证明完整实体 ID。Node 仍需
完整全页稳定、唯一活动 Tab、无 Dialog、同主 Frame/Loader 和精确原引用，输入后再采集
确认。新文档或业务实体更换产生不同 ID，不能借新 Revision 把旧动作转移到新目标。
