# 虚拟列表业务实体语义围栏闭环

日期：2026-09-12。承接 progress 165/167 的 A03；本切片补齐同名业务行绑定。

## 最近业务实体成为 Element ID 的内部围栏

State Collector 在采集交互目标时，向上最多检查十二层最近业务实体容器。应用可用
`data-agent-entity-id`、`data-entity-id`、`data-row-key`、`data-item-key` 或 `data-key` 提供稳定
实体键；未提供显式键时，`row/listitem/treeitem/tr/li` 的规范化可见文本作为保守 fallback。
目标自己的 DOM path、frame、role、名称、control type、Route 和 Tab 围栏保持不变。

业务上下文只在 Node 内的页面采集返回值中短暂存在，进入 State Hash、Target Registry 或
Element ID 前立即做带版本域分隔的 SHA-256，并清除原文。Browser State、公开 API、Agent、
Audit 和持久化均不新增业务键、行文本或上下文哈希字段。相同 DOM 路径、相同按钮名称和类型
若被虚拟列表复用于另一业务实体，Element ID 与 Target Revision 会变化；Batch 在每个动作前
基于最新真实 State 重绑定，因此旧 ID fail-closed，不会静默点击新记录。

## 边界

- A03 仓库内通用代码项关闭。没有稳定业务键且容器可见文本也完全相同的两条记录，通用浏览器
  基础设施无法凭空推断领域主键；站点 Adapter 应提供上述实体属性或更高层领域 Selector；
- 页面可在任意时刻恶意或竞争性变更。Node 已在 Batch 开始及每项动作后重采真实 State，本切片
  关闭的是虚拟列表常见的同路径/同名业务实体复用，不宣称消除浏览器固有 TOCTOU；
- 行内状态变化会使 fallback 指纹失效并安全中止后续旧 ID。A06 将继续把动态页面长 Batch
  缩为变化驱动的微批次；A20 继续处理 DOM/Layout/Network/Focus/Route 组合稳定性。
