# 远程桌面输入帧围栏与过期点击释放

> 日期：2026-09-28
> 范围：Web/Tauri 共用 noVNC、Browser Node Remote Desktop Gateway、Integration 端口分配。

## 改动

noVNC 通过私有伪编码声明输入帧能力。在 `ABCF` 图像 Fence 经过 Canvas flush 和下一动画帧后，客户端保存该帧的来源 ID，并在后续键盘、鼠标和剪贴板输入前发送独立的 `ABCI` Fence，携带 `based_on_frame_id`。Gateway 只接受已协商能力的标记；输入 ID 必须同时等于该连接已确认绘制的 Frame ID 与共享上游最新图像 ID。缺标记、错误 ID、尚未绘制的新帧或已变化的画面均不转发输入，而请求最新画面。静止页面的图像 ID 未变化时，即使采样时间较久也保持可操作；判定使用同一 Gateway 的单调帧身份，不依赖客户端时钟。

Gateway 只为协商客户端追踪有界的按键和鼠标按下状态；拒绝过期输入时向共享上游发送释放事件，关闭连接时也释放。拒绝旧画面的鼠标按下后，持续按住的按钮须先松开才能再次按下，避免新帧到达时把旧拖拽变成新点击。同一连接一旦声明能力，后续 `SetEncodings` 撤回声明也不能降级。旧客户端从未声明私有能力时沿用原输入行为；该兼容路径还没有 Frame ID 围栏，因此不能宣称所有远程输入均受此保护。

CI 的 Integration 曾因脚本分别 bind/close 14 个随机端口，把同一个端口同时分给事件 gRPC 和第二个 Control Plane HTTP，导致启动失败。脚本现同时持有所有候选 socket，确认端口互不重复后统一释放；这属于测试环境碰撞修复。

## 验证与边界

- Gateway 35 项通过，含真实 TCP/WebSocket/RFB 的当前帧点击转发、过期点击拒绝和上游鼠标释放；严格 Clippy 通过。
- Web 145 项与 noVNC 协议 4 项、Lint、生产构建、补丁锁文件 frozen install 通过。
- Integration 端口分配脚本通过 Shell 语法检查；完整 Integration 与远端 CI 仍需以本提交的运行结果核对。

Viewer 尚未展示来源到绘制的有效帧龄；Gateway 尚未把输入的有效帧龄发布为逐连接指标。未声明私有能力的旧 Viewer 仍无输入围栏。浏览器动画帧回调不证明物理显示器呈现，目标 Linux 八客户端小时级长稳与硬件 Codec 仍是独立 Gate。
