# 当前剩余实现与前端技术质量审计

> 审计日期：2026-07-28
> 审计基线：Media 闭环实现后的 2026-07-28 工作树
> 来源：`docs/outline/` 三份大纲、OpenAPI、数据库迁移、Control Plane、Browser Node、
> Web Console、部署清单和测试证据

## 结论

当前仓库已经具备可运行的 Browser/Coordinator/Agent 主链、AUTO 资源策略、真实
PostgreSQL 状态、Operation/ACK、资源 SSE、Business Recovery Ready Gate、企业运营
数据面和 Tauri 2 安全容器基线，不是只有页面或接口骨架。

但是项目仍未达到 V16 全量生产发布状态。剩余工作必须区分：

| 类型 | 结论 |
| --- | --- |
| 可直接继续开发 | 业务 Adapter/Provider 证明/契约作者 UI、Import/Saved View/Proxy Binding 等 Web 产品能力、Group/Tags 批量生命周期与列表投影优化、Hot Tenant 持久迁移、State/Audit 事件统一、Phase 4 高级 Agent、企业运营自动编排 |
| 目标环境 Gate | Linux Cgroup/多 Node 长稳、GPU/LSM、目标云 CNI/CSI/KMS/IAM、真实 IdP、桌面签名发行、真实多 Region |
| 组织 Gate | Owner/RACI、Threat Review、Residual Risk、Staging、发布审批、值班和 Pager 到达签字 |

因此当前版本可以继续用于本地/集成开发和受控验收，但不能据此宣称已经可以处理真实
客户生产数据。

## 已用代码确认的主要缺口

### P0：生产发布阻断项

1. **目标 Linux/目标云长期证书未关闭**
   - 本机已有真实 Chrome 500 次顺序与并发 4 容量证书；
   - 仍缺目标 Linux 多 Browser Node 的 Cgroup v2、OOM/PSI、Xvfb/x11vnc、
     Extension、Media、磁盘与网络长期压力证书；
   - 仍缺真实双 Browser Node + Object Storage + Chromium 的迁移、故障注入和恢复验证。
2. **生产安全与信任根未关闭**
   - 缺 GPU Helper、AppArmor/SELinux/Landlock 强制策略与跨 UID 集群验收；
   - 缺 Offline Root/HSM、OCI Admission 强制验签、CRL/SPIFFE 撤销和目标云 KMS/IAM；
   - 缺真实企业 IdP Claim/MFA/ACR/Logout/租户映射联调。
3. **发布和运营组织 Gate 未关闭**
   - 缺 Primary/Secondary Owner、RACI、Threat Review、Residual Risk 和发布签字；
   - 缺真实 Staging 制品下载后验签、升级/回滚证据与 Pager 到达演练；
   - Apple/Microsoft 签名、Notarization、Windows 真实机器和更新源尚未验收。

### P1：下一批应实现的产品能力

1. **业务站点 Adapter 与恢复证明**
   - 通用安全 Lease、Application Recovery Contract、持久 Verdict 和迁移 Ready Gate
     已完成；
   - `maximumAutoRecovery` 已在 V034 接入持久尝试预算、受限 Reload/Refresh/导航、
     Node State ACK 与二次 Ready Gate；仍缺受信 `RESTART_EXTENSION` 动作；
   - 缺目标站点的支付、账号安全、SPA/Form、关键事务 Adapter，缺 Provider/API 级
     账号、权限和业务实体证明，也缺契约作者 UI。
2. **Hot Tenant/Shard 生产迁移**
   - 当前 `CoordinatorShardRouter` 使用进程内 `ConcurrentHashMap` 和 `AtomicLong`；
   - 只有安全点重分区模型和单测，尚无 PostgreSQL 权威 Route Epoch、旧 Owner 拒绝、
     跨 Coordinator/Shard 迁移、回滚与压力证书。
3. **State/Audit 统一事件层**
   - Resource/Migration 已有 PostgreSQL SSE、事务游标、断线重连和序列校验；
   - State/Audit 仍使用各自读取路径，缺统一事件信封、跨 Region Event Bus、断点重放
     和 Web 轮询替换。
4. **Web Console 产品能力**
   - Workspace Groups 的 PostgreSQL 权威模型、OpenAPI、RBAC、幂等审计、Session
     归属、默认 AUTO 策略继承和正式 UI 已在 V033 完成，不再读取生产 Fixture；
   - Workspace Tags 的 V035 权威模型、API、Session 归属/投影和正式 UI 已完成；仍缺按
     Group/Tags 的批量生命周期操作、服务端组合过滤和批量查询投影；
   - 全局搜索、通知、主题按钮明确禁用；
   - Environment/Profile Import、Saved View、Proxy Binding 和环境“更多操作”未接 API；
   - Workspace Settings 的工作区名称、默认 Runtime/Region/HumanTakeover 已在 V036
     接入 PostgreSQL、正式 API、RBAC、幂等和审计；仍缺 Proxy Binding、Import、
     Saved View 和环境更多操作；
   - Runtime Build 已成为正式创建绑定；Agent Policy 及 Agent/Extension 列表投影仍未
     成为完整的一等创建/查询契约；Group/Tags 已有基础投影，但仍需批量化以关闭 N+1；
   - TypeScript Client 尚未由 OpenAPI 自动生成和发布。
5. **Phase 4 Agent 生产增强**
   - 缺 Network/Toast/Dialog/Visual/Login/Business Entity Validator 和组合 DSL；
   - 缺独立无宿主权限 Agent Worker、Reviewer Agent、真实模型治理和大规模 Replay；
   - 缺 Challenge Detection、一次性 HumanAssist、协作取消、跨 Region Workflow；
   - 缺完整 State 分类、截图敏感区模糊和 Purpose 绑定访问控制。
6. **Phase 7 自动编排**
   - Validation Farm、GameDay 和 Region/DR 已有真实数据库/API/证据模型；
   - 当前 Validation 和 GameDay 仍由 API `start/complete` 登记结果，缺隔离 Worker 队列、
     自动浏览器矩阵、真实故障执行器和大规模回归；
   - 缺 Burn Rate 自动冻结发布、GameDay 失败联动发布系统；
   - 缺真实 Region Authority、数据库/对象复制、流量切换和 RTO/RPO 演练；
   - 当前交付 Terraform Module，不是 Terraform Provider；
   - 四语言 SDK 是手写契约测试型实现，缺自动生成、签名、版本发布和兼容策略。

### P2：生产深度与完整性

1. Warm Tier Delta Journal、Multipart Resume、原生 Region Resync、流式 Snapshot、
   Backpressure 和熔断；
2. Proxy Reputation/Provider Score、多供应商优化、短期 Secret 和真实 DNS/Provider

3. 独立 Secure Debug Worker、像素级强制录像和 WORM Recording Manifest；

5. Browser/Profile I/O 是 Browser Cgroup 聚合信号；只有明确计费需求时再补路径级归因；
6. Session Ownership 批量投影与列表 N+1 优化、双 Coordinator 下数据库连接池/GC/

### 详细发现

#### P1：Accessibility

1. **弱对比小号文本**
   - 位置：`apps/web-console/src/index.css` 的 `--color-text-muted`；
   - 影响：`#697b89` 在 `#111a24` 上约为 4.01:1，10—12px 普通文本不满足 WCAG
     1.4.3 的 4.5:1；
   - 建议：提高 muted token 明度，并对 Surface 1/2/Canvas 做自动对比回归。
2. **Settings 标签关联已关闭**
   - `SettingGroup` 现在通过 `htmlFor` 关联工作区名称、Runtime、Region 和
     HumanTakeover 控件；
   - 仍需对全站表单和组合控件执行自动 axe/ARIA 与真实屏幕阅读器回归。
3. **触控目标普遍小于 44×44**
   - 位置：顶部栏、列表操作、侧栏等多处 `h-8 w-8`、`h-9`；
   - 影响：窄屏和触控设备误触风险较高；
   - 建议：桌面可保留高密度视觉尺寸，但用不可见 padding/伪元素把命中区扩大到 44px。
4. **缺完整辅助技术验收**
   - 当前有全局 focus-visible 和 reduced-motion，Viewer 窄屏 E2E 已通过；
   - 仍缺全键盘操作、焦点陷阱、屏幕阅读器、浏览器缩放 200% 和自动 axe/ARIA Gate。

#### P2：Performance / Responsive / Theming

1. **Session Detail 路由包较大**
   - 生产构建 `SessionDetailPage` 约 440.27 kB；
   - 建议按 Remote Desktop、Resource Chart、Migration/Recovery 抽屉继续懒加载。
2. **Settings 基础窄屏布局已关闭**
   - 小屏使用横向可滚动分区导航，`lg` 以上才恢复 200px 二级导航；
   - 仍需增加 1280×800、390×844 管理员路由、200% 缩放和长文本截图回归。
3. **少量组件绕过主题 Token**
   - noVNC 背景与 Resource Chart 使用硬编码 HEX/RGBA；
   - 建议抽出 desktop-canvas/chart-grid/chart-series Token，避免未来主题切换漂移。
4. **主题切换尚未实现**
   - 当前深色主题本身一致，但顶部主题按钮禁用；
   - 如果产品确定只支持深色，应移除无效入口；如需浅色，则补 Token、持久化和系统主题同步。

### 正向结果

- Web lint、37 项 Vitest 和生产构建全部通过；
- 路由级懒加载已生效，核心页面不是单一巨大入口包；
- 全局 `focus-visible` 与 `prefers-reduced-motion` 已实现；
- 真实 API 页面具有 Loading/Error/Empty/Offline/Operation 状态，没有用前端定时器伪造
  资源曲线或扩容；
- 生产业务路由已不再引用 Mock/Fixture 数据；
- 设计 Token、权限路由和 Web/Tauri 平台适配层已经形成可复用基线。

## 推荐实施顺序

1. **P1 `/harden`**：先补业务 Adapter/Provider 恢复证明、Hot Tenant 和统一事件的
   失败/幂等/权限边界；
2. **P1 `/normalize`**：把 Saved View、Import、Proxy Binding 和全局入口接入正式
   领域 API，补齐 Group/Tags 批量生命周期与批量查询，并统一 Operation/错误模型；
3. **P1 `/adapt`**：补 Settings/Enterprise/Session Detail 的窄屏与 200% 缩放布局；
4. **P1 `/clarify`**：移除或明确所有不可用入口，避免把展示型设置误认为已保存；
5. **P2 `/optimize`**：拆分 Session Detail 重型依赖和图表/远程桌面路由块；
6. **P2 `/polish`**：统一主题 Token、触控命中区、标签关联和细节回归。

完成上述修复后应重新执行 `/audit`，比较技术质量得分和剩余发布 Gate。
