# 当前未实现清单

> 审计日期：2026-07-26
> 基线：本文件所在 `main` 提交
> 大纲来源：`docs/outline/` 下代码骨架、V16 架构设计和开发实施计划
> 判定口径：代码、契约、迁移、自动化测试、运行证据和运维闭环缺一时，不判定为生产完成。

## 结论

当前仓库已经完成可运行的单 Region 工程 PoC、Phase 4 Agent MVP，以及 Phase 5/6
的一批 Stage A 能力；尚未达到 V16 的生产完成标准。剩余工作分为三类：

| 类型 | 结论 |
| --- | --- |
| 代码尚未实现 | Phase 7 绝大多数领域、Phase 3 业务恢复、Phase 4 高级 Agent、Phase 6 Browser Capacity、Web Console 三个领域和实时事件等 |
| 已有骨架或 Stage A | Coordinator/Browser 容量、Runtime Registry、Retention 字段、Kubernetes 清单、State Region fallback 等，不能算生产闭环 |
| 代码已具备但缺生产验收 | 目标云 CNI/CSI/Object Storage/IAM、真实 IdP、LSM、HSM/Offline Root、Rolling Upgrade 与长稳 |

## 按阶段列出的未实现项

### Phase 0：工程和契约

技术链路已基本完成，剩余主要是组织和发布 Gate：

1. 核心模块 Owner/RACI 的正式分配与签字；
2. 架构冻结、Threat Review、Staging 验收和发布审批记录；
3. N/N-1 契约兼容与升级/回滚的完整 Release Gate。

### Phase 1：Browser Runtime

1. 真实 Chrome 500 次顺序启动/终止证书已完成；Xvfb/x11vnc 桌面模式和目标 Linux
   长稳仍待完成；
2. CPU、内存、PID、磁盘和网络的强制 Cgroup/Runtime 上限；
3. Renderer/Browser/Node 长稳故障组合和并发容量 P95/P99；
4. GPU Helper、GPU/Media 资源隔离和压力治理。

### Phase 2：Session Coordinator

单 Session 的 STARTING、RUNNING、RECOVERING、TERMINATING、HumanTakeover
全阶段，以及 Agent pending/已执行未提交故障接管已经闭环。剩余：

1. 双 Coordinator 同时长稳运行，注入数据库延迟、连接池拥塞和时钟偏差；
2. Hot Tenant 跨 Shard 安全点迁移、旧 Route Epoch 拒绝和压力测试；
3. Session Ownership 批量投影，消除列表读取的潜在 N+1；
4. Reconcile 指标和 Alert Rule 制品已完成；目标 Prometheus 跨 Pod 聚合、
   Alertmanager/Pager 到达与关闭演练仍待完成。

### Web Console

1. Nodes、Extensions、Groups 正式领域模型、数据库、API 和页面；当前生产路由只会
   fail-closed，开发数据仍来自 Fixture；
2. 完整九步 Session 创建向导，补 Persona、Extension、Agent Policy 等后端契约；
3. 统一 SSE/WebSocket 事件层、断线重连和序列校验，替换 State/Audit 轮询；
4. 从 OpenAPI 生成 TypeScript Client，并做 N/N-1 兼容验证；
5. 与真实企业 IdP 完成 Metadata、Claim、MFA/ACR 和 Logout 联调；
6. 全局搜索、通知、主题和用户菜单的真实功能；
7. GitHub Actions 中的完整浏览器 E2E、桌面视觉回归、全键盘和屏幕阅读器验收。

### Phase 3：Profile、Proxy、State 与 HumanTakeover

1. Profile `Login Required`/`Business Ready` 验证器，以及 SQLite、LevelDB、Cookie
   等 Application-aware Adapter；
2. Warm Tier Delta Journal、跨 Region Archive/Restore、KMS 和真实 IAM；
3. 基础设施级出口防逃逸、真实 Proxy Provider、短期 Secret、分布式健康和 DNS/
   Provider 故障演练；
4. 原生 Region Resync、Chunk/Checksum/Commit、流式 Snapshot、Backpressure、
   Resync Budget 和熔断；
5. HumanTakeover 的本地双向 TCP 网络分区已闭环；目标云单向分区、丢包和多客户端
   竞争矩阵仍待完成。

### Phase 4：Agent 生产增强

开发计划中的 MVP Gate 已关闭，V16 增强项仍缺：

1. Network、Toast、Dialog、Visual、Login、Business Entity Action Validation，
   以及 All/Any/Sequence/Negative 组合 DSL；
2. 独立无宿主权限 Agent Worker Sandbox、固定 IPC 和单独故障域；
3. Reviewer Agent、真实模型 Provider/模型治理和 Production-like Replay；
4. Challenge Detection 与 `allowed_action_count=1` 的一次性 HumanAssist；
5. 已下发动作的协作取消、复杂补偿和跨 Region Agent Workflow；
6. 完整 State 分类、截图敏感区域模糊和 Purpose 绑定访问控制。

### Phase 5：可靠性、安全与审计

1. GPU Helper、AppArmor/SELinux/Landlock 强制策略、独立 Audit Identity 和真实集群
   跨 UID/互相崩溃验收；
2. 独立 Secure Debug Worker、像素级强制录像和 WORM Recording Manifest；
3. Offline Root/HSM、OCI Admission 强制验签、撤销和生产回滚演练；
4. 在线信任根双写、CRL/SPIFFE 撤销和过期证书演练；
5. Legal Hold 工作流、删除 Receipt 和签名 Audit Export Manifest；
6. 目标云 Object Storage/KMS/IAM、Multipart Resume 和跨 Region Restore；
7. 目标云 Ingress/CNI 单向网络分区及 Provider 故障矩阵。

### Phase 6：密度与 Kubernetes

1. 端到端 Coordinator Capacity Certificate：PostgreSQL/gRPC、GC 长稳、
   Mailbox Byte Budget、Passivation/恢复和多实例调度；
2. 真实 Chrome 500 次顺序生命周期证书已完成；并发 Browser Capacity Certificate、
   Extension Weight/Probation、PSI/Cgroup 深度采样、Node Pressure 驱逐和资源硬限制；
3. 双 Coordinator Hot Tenant/Shard 迁移压测；
4. 目标云多节点 CNI 防直连、CSI Snapshot 一致性和独立 Browser Node Pool 验收；
5. Operator Watch/Informer、指标/告警、API Server 故障长稳；
6. N/N-1 Rolling Upgrade、Rollback 和 Pod/Node Kill GameDay；
7. Media/GPU Capacity 和 Extension Anti-affinity 调度模型。

### Phase 7：企业运营

除 Runtime Registry、发布/禁用治理和只读 UI 的基础切片外，以下核心能力尚未实现：

1. Runtime Validation Farm、隔离验证 Worker、Persona/能力观测；
2. Production-like Replay Dataset 和 Runtime Compatibility Matrix；
3. Cost-aware Scheduler、版本化 Rate Card 和可复算 Cost Breakdown；
4. SLA/SLI/SLO、Error Budget、Burn Rate 和发布冻结；
5. Retention Policy Engine、Compliance Service、Residency Gate、License Inventory；
6. Recovery GameDay 领域模型、Runner 和 RTO/RPO 自动证据；
7. Media Resource Class 和高权限 Extension Isolation；
8. Multi-region Authority、复制、故障切换和 DR；
9. Terraform/IaC 模块；
10. 正式生成 SDK；`apps/cli` 当前为空，多语言 SDK 尚未开始。

## 建议实施顺序

1. 先关闭 Phase 1/3/5 的生产安全边界：资源硬限制、Profile Business Ready、
   LSM/GPU Helper、基础设施出口防逃逸和证书撤销；
2. 完成 Phase 6 两类容量证书、Hot Tenant 迁移和目标云 Rolling Upgrade；
3. 补 Web Console 实时事件、生成 Client 和 Nodes/Extensions/Groups；
4. 以 Runtime Validation Farm + Replay/Compatibility 启动 Phase 7；
5. 再建设 Cost/SLA/Retention/Compliance/GameDay，最后推进 Multi-region/DR、
   Terraform 和多语言 SDK。
