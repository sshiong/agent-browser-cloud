# 稳定区域原生表单重置事件与旧观察器补装

> 日期：2026-10-07
> 基线：dbcd3c95f4c216db3d69a1ad63b35365dfbb10de
> 范围：主 Frame 的原生 reset 区域历史；不开放区域动作。

## 真实缺口

progress 278 的原生 checked setter 候选机制不能覆盖浏览器内部表单重置。自有
Chrome 先将 checkbox.checked 置 true，再执行 form.reset 恢复默认 false：确实
改变后恢复，但 checked 原生 setter 断点的只追加计数增量为零。

另一个自有页面先将默认 checked=true 的 checkbox 置 false，建立区域观察，再
执行 form.reset，确认 checked=true，立即恢复为 false。隔离 Mutation 计数为零、
CSS.styleSheetChanged 增量为零；独立捕获到一条 reset 事件。旧 region_observer.js
在这个往返后保留原 lastEventSequence。初次探索受观察器初始化影响，不作为 reset
事件证明；等待连续两次相同区域序号后复验，旧序号明确没有变化。

新增实际 State Collector 的真实 Chrome 回归先让独立自有 Form 中的按钮取得
三样本/两秒 readiness，再执行上述真实往返。基线生产代码在精确断言
`native form reset and restored checked state must invalidate the related region`
失败，exit 101 / 0 passed / 1 failed；没有修改测试上限或普通动作围栏。

## 实现

- 主 Frame 的 Node 隔离观察器增加 capture reset 监听，复用原 touch 的实例/祖先/
  实体容器关系。Form 事件目标覆盖自己的控件与实体容器，不重置无关 Form 的区域。
- 注册幂等，已存在的 ledger 也会补装；补装时先推进序号并使全部旧 watched 窗口
  重建，不将之前漏掉的 reset 历史当成连续证明。
- 原 Mutation/Resize/Interaction 路径和序号耗尽 fail-closed 保持。监听不读取表单
  值、凭据、OTP 或事件正文，不使用 Debugger、键盘/文本输入或外部模型。
- 不改变 API/Protobuf/数据库/SDK，不把区域证明变为执行 Grant；普通全页静默、
  Domain、实体身份、Secret、高风险、事务与真人输入优先级门禁保持。

## 实际验证

真实 State Collector 同一回归已验证：

1. 精确 Form 按钮在往返后失去 readiness，原无关实体按钮仍 ready。
2. 相关按钮重新建立完整窗口。
3. 从同一隔离 World 移除监听和标记，模拟保留 nonce/元素实例的旧 ledger；下次
   正式采样补装，旧窗口失效，然后可重新建立。
4. 移除独立自有 Form 后，让原实体按钮重新取得 readiness，再继续原 Mutation/
   CSSOM/动画/克隆和未知 POST 回归；没有让旧回归从已失效窗口起步。
