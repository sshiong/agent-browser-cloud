# Agent Browser Cloud — 合规审计与整改记录

> 审计日期：2026-07-23  
> 审计基线：代码大骨架、V16 最终架构设计、开发流程与实施计划  
> 审计范围：仓库文档、Java Control Plane、Rust Browser Node、React Web Console、Contract、数据库、CI 与本地容器编排

## 1. 结论

整改后的仓库已经达到“可构建、可测试、可在隔离本地环境启动、可验证 CP↔Node 基础链路”的 PoC 基线。Phase 0 的技术项基本闭合，Phase 1/2 为部分实现。

仓库仍未达到 V16 的生产合规标准。认证、mTLS、持久化 Node Journal、事件持久重投、真实 Chromium/CDP、Human Takeover、完整审计与治理能力均属于明确的发布阻塞项。不得把当前版本用于真实客户数据或对外生产流量。

## 2. 基线符合性

| V16/实施计划要求 | 当前证据 | 结论 |
|---|---|---|
| PostgreSQL 是控制面权威来源 | Session、Context、Operation、Ownership、Idempotency、Outbox 均落 PostgreSQL | 符合当前阶段 |
| 所有写操作进入 Session Coordinator | Start/Terminate 经 Application Service 和 Coordinator；Create 为独立创建事务 | 基本符合 |
| 单 Session 单 Active Operation | PostgreSQL Partial Unique Index + 事务行锁 | 符合 |
| Term/Epoch/CAS 防止旧写覆盖新状态 | 核心字段已进入 Domain/Proto/JPA/SQL，Context Append 校验 Epoch | 符合 PoC |
| Coordinator 热路径不等待 Node 网络 I/O | 事务内写 Outbox，后台定时投递 gRPC | 符合 |
| 至少一次投递必须幂等 | API 幂等持久化；Node `message_id` 去重 | 部分符合，Node 重启后不保留 |
| Node 不直接写控制面业务表 | Node 仅执行 gRPC 命令和本地 Runtime 操作 | 符合 |
| Schema First 与三语言生成 | Buf/Proto/OpenAPI/JSON Schema + Java/Rust/TypeScript 生成目录 | 符合 |
| 全新数据库必须可迁移 | PostgreSQL 17 隔离容器 + Flyway 10.22.0 烟雾测试 | 符合 |
| CP↔Node 必须有真实 Ping/Dispatch | Tonic Server + Java gRPC Client + 集成烟雾测试 | 符合基础链路 |
| Runtime 生命周期与事件闭环 | RuntimeStarted/Stopped 已通过独立 gRPC、Inbox 与 Coordinator 提交在线闭环 | 符合 PoC；重启恢复仍不符合生产 Gate |
| Tenant 身份不可由客户端自报 | 当前 `X-Tenant-Id` 只做本地归属校验 | 不符合生产 |
| Node 身份与链路加密 | 当前内部 gRPC plaintext | 不符合生产 |
| 审计、保留、删除证明闭环 | 只有表结构，没有完整写入与运营流程 | 不符合生产 |

## 3. 已修复问题

| 严重度 | 原问题 | 整改 |
|---|---|---|
| P0 | 根目录没有可用 Gradle Wrapper，Control Plane 依赖无法解析 | 增加 Gradle 8.9 Wrapper、Java 21 Toolchain 和统一根构建入口 |
| P0 | Flyway Core/数据库模块版本混装，应用运行时 `AbstractMethodError` | 统一为 Flyway 10.22.0，并在 PostgreSQL 17 上实测迁移 |
| P0 | JPA Entity 不在启动类默认扫描范围，应用无法启动 | 在 `BootstrapApplication` 增加显式 Entity/Repository 扫描 |
| P0 | `@Validated` Controller 为 final，Spring 无法创建代理 | 允许 Spring 生成校验代理 |
| P0 | JSONB 字段按 VARCHAR 绑定，Session 创建返回 500 | 使用 Hibernate JSON JDBC 类型绑定 |
| P0 | Java Coordinator Bean 缺失、Repository 扫描不完整 | 增加 Coordinator 配置与完整扫描 |
| P0 | Node Gateway 是运行即抛异常的 Stub | 改为事务 Outbox + 后台 gRPC Dispatcher |
| P0 | Rust Input Sandbox 无法编译 | 修复借用错误并通过 workspace test/clippy |
| P0 | Browser Node 没有可工作的 RPC 服务 | 实现 `Ping/Dispatch`、ACK、Term 检查和进程内去重 |
| P1 | Contract 只有零散 Proto，无生成/校验闭环 | 增加 Buf、OpenAPI、JSON Schema、四类 Proto 和三语言输出 |
| P1 | API 列表未实现、租户详情可误读、无持久幂等 | 增加分页列表、租户归属校验和 PostgreSQL 幂等记录 |
| P1 | Outbox 序列化失败被吞掉，可能发布 `{}` | 改为事务失败并回滚 |
| P1 | 网络投递包在数据库事务中 | 将 gRPC 调用移出数据库事务，并增加超时、退避与 Dead Letter |
| P1 | Node 只 ACK 命令，Session/Operation 永久停留在中间态 | 增加 Node Event gRPC、Inbox 去重、版本校验及 Start/Terminate 终态提交 |
| P1 | Compose 暴露不必要端口并把迁移当初始化 SQL | 仅本地绑定公开服务，CDP/gRPC 保持内部，迁移由 Flyway 管理 |
| P1 | 缺 Dockerfile、CI、锁文件、非 watch 测试命令 | 补齐三类镜像、GitHub Actions、Cargo/Pnpm Lock 和确定性命令 |
| P2 | Actuator 永远显示详细健康信息 | 仅暴露 health/info，详情设为 never |
| P2 | Web Console 缺基础响应安全策略 | Nginx 增加 CSP、点击劫持、MIME、Referrer 和 Permissions Policy 响应头 |

## 4. 未关闭的安全发现

### [SEC-001] 高：REST API 没有真实认证

- 位置：`apps/control-plane/src/main/java/io/browsercloud/api/SessionController.java`
- 现状：调用方可以自报 `tenantId` 或 `X-Tenant-Id`；当前校验只能防止误读，不能抵抗恶意调用方。
- 要求：接入 OIDC/JWT 或等效身份层；Tenant 必须从已认证 Principal 派生；创建请求不得信任正文里的租户身份。
- 发布状态：阻塞生产。

### [SEC-002] 高：Control Plane 与 Browser Node 之间是明文 gRPC

- 位置：`apps/control-plane/src/main/java/io/browsercloud/infrastructure/NodeCommandOutboxDispatcher.java`、
  `NodeEventGrpcServer.java`
- 现状：命令客户端使用 `usePlaintext()`，Node Command Server 与 Control Plane Event
  Server 均未校验对端身份。
- 要求：启用双向 TLS、节点证书轮换、证书吊销和服务级授权。
- 发布状态：阻塞生产。

### [REL-001] 高：Node 幂等与 Term 状态不持久

- 位置：`apps/browser-node/crates/node-agent/src/main.rs`
- 现状：`completed` 与 `coordinator_terms` 为进程内 Map，重启后会遗失。
- 要求：实现 SQLite Node Journal；在执行副作用前持久化 Inbox/Claim，在重启后返回原 ACK 并拒绝旧 Term。
- 发布状态：阻塞 Phase 1/2 Gate。

### [REL-002] 中：Node Event 在线闭环已完成，崩溃后持久重投未完成

- 位置：`packages/contracts/proto/node/v1/node_command.proto`、`apps/browser-node/crates/node-agent/src/main.rs`
- 现状：`RuntimeStarted/RuntimeStopped` 已携带 Tenant、Term、Epoch、Sequence 和 Generation，
  经 Control Plane Inbox 去重并由 Coordinator 提交；但 Node 的已完成命令与待确认事件仍在内存。
- 要求：使用 SQLite Journal/Outbox 保存副作用结果和待确认事件，Node 重启后继续重投；
  同时接入 Browser Crash/Runtime Failed 主动事件。
- 发布状态：阻塞 Phase 1/2 Gate。

### [REL-003] 中：Outbox 多实例 Claim 未实现

- 位置：`apps/control-plane/src/main/java/io/browsercloud/infrastructure/NodeCommandOutboxDispatcher.java`
- 现状：多个 Control Plane 实例可能同时读取同一未发布事件；Node 幂等可减少重复副作用，但不能替代 Claim。
- 要求：使用 `FOR UPDATE SKIP LOCKED`、租约 Claim 或等效原子状态转换。

### [WEB-001] 低：CSP 仍允许内联样式

- 位置：`apps/web-console/nginx.conf`、`apps/web-console/src/**/*.tsx`
- 现状：React 页面大量使用 `style` 属性，因此 CSP 需要 `style-src 'unsafe-inline'`。
- 要求：迁移到静态样式表或基于 Nonce/Hash 的方案，再移除该策略。

## 5. 验证命令

```bash
make ci
make build
make contracts
make test-integration
docker compose config
pnpm --registry=https://registry.npmjs.org --dir apps/web-console audit --audit-level high
```

`make test-integration` 会创建名称带随机后缀的临时 PostgreSQL/Redis 容器，启动真实 Java/Rust 进程，验证健康检查、迁移、API 幂等、租户隔离、Node Command ACK、Runtime Start/Stop Event、Inbox 去重与 Operation Commit，结束后清理临时资源。

前端供应链审计最初发现旧 Vitest/Vite 的 Critical/High 公告；升级到 Vitest 3.2.7、Vite 6.4.3 和兼容的 React Plugin 后，完整依赖审计返回 `No known vulnerabilities found`。

## 6. 审计边界

- 本次没有把尚未进入计划阶段的 Phase 3—7 接口骨架误判为已实现。
- 本次没有完成真实 Chromium、VNC、Kubernetes、KMS、OIDC、消息总线或企业运营系统的外部集成。
- `docker compose config` 已通过；本机 Docker Daemon 配置的 USTC 镜像站在拉取 Temurin 基础镜像时返回 EOF，因此三类镜像的完整 `docker build` 未在本机完成，CI/可用 Registry 中仍需补跑。
- 安全检查按 Java/Rust/React 常见安全实践和 V16 威胁模型执行；它不替代渗透测试、供应链扫描、合规认证或生产演练。
